## 1. 핵심 관점: 업무의 흐름과 SSOTA의 위치

보통의 업무는 세 단계를 거친다.

```
리서치  →  기획  →  제작
(조사·수집)  (분석·구조화)  (결과물 생산)
```

각 데모 레벨이 커버하는 범위:

| 업무 흐름 | Level 1 | Level 2 | Level 3 |
|-----------|---------|---------|---------|
| **리서치** (조사·수집) | 웹 검색 → 캔버스 정리 | + URL 스크래핑, JSON 추출 | + 심층 리서치 (서브 에이전트) |
| **기획** (분석·구조화) | — | 비교 분석, 인사이트 도출, 관계 시각화 | + 기획안 작성·구조화 |
| **제작** (결과물 생산) | — | — | 슬라이드, 영상, 견적서, 마이크로앱 |

- **Level 2까지** = **리서치 자동화 + 기획 보조**. "조사하고 정리하는 건 AI가 하고, 나는 판단만 한다."
- **Level 3** = **제작까지**. "생각만 말하면 결과물이 나온다."

## 2. SSOTA의 큰 주제: Personal Agentic Computing

### 왜 "AI 캔버스"를 넘어서야 하는가

Level 1–2까지는 "AI 캔버스"로 설명이 된다. 하지만 Level 3 이후에는:

- **앱(App)**: 블록 타입을 정의하고, 결과물을 생산하는 확장 단위
- **커스텀 서브 에이전트**: 유저가 자기만의 자동화 워크플로우를 정의
- **앱 마켓**: 커뮤니티가 앱을 만들고 공유

이것은 더 이상 "캔버스"가 아니다. **컴퓨팅 환경**이다.

### "OS"는 어렵고, "컴퓨팅"은 정확하다

| 후보 | 장점 | 단점 |
|------|------|------|
| AI Canvas | 직관적, Level 1–2 설명에 적합 | Level 3 이상의 앱·서브에이전트를 담지 못함 |
| AI OS | 기술적으로 정확 (데이터+도구+앱+에이전트 통합) | "OS"가 무겁고 어려운 단어. 유저가 거부감 |
| Agentic OS | 에이전트 네이티브 설계를 강조 | 여전히 "OS" 부담 |
| **Personal Agentic Computing** | PC(Personal Computing)의 역사적 맥락 활용. "개인을 위한 에이전트 컴퓨팅"이라는 새 카테고리. 기술적으로도 정확 | 다소 길지만, 투자자 피치에는 오히려 강점 |
| AI 컴퓨터 | 유저에게 가장 쉬움. "말하면 다 되는 내 컴퓨터" | 투자자에게는 너무 단순할 수 있음 |

### 결론: 청중에 따라 분리

| 청중 | 메시지 | 키워드 |
|------|--------|--------|
| **투자자** | AI 에이전트 시대의 매킨토시. Personal Agentic Computing. | 매킨토시 모먼트, 새로운 컴퓨팅 패러다임 |
| **유저** | 말하면 다 되는 AI 컴퓨터. 다른 도구를 배울 필요 없음. | AI 컴퓨터, 코드 없이, 한 마디로 |

## 3. 1인 기업 = 100인: 소비자 넘어선 포지션

### 3.1 고민의 출발

"Personal Agentic Computing", "말하면 다 되는 AI 컴퓨터"로 프레이밍하면 **소비자·개인 도구** 쪽 인상이 강해진다.  
하지만 SSOTA의 목표는 "개인이 쓰기 좋은 AI 캔버스"에서 멈추지 않는다.

- **원하는 것**: 1인이 100인 기업의 생산성을 갖는 흐름.
- **수단**: 서브 에이전트 + 업무 흐름(Skill) 정의로, 100명이 하던 일을 한 사람이 설계·실행할 수 있게 하는 것.
- **따라서**: 단순히 소비자 사이드에만 있는 게 아니다. **모든 사람이 1인 기업이 되는 인프라**로 가고 싶다는 게 목표다.

이걸 명확히 하기 위해 "1인 = 100인" 프레이밍과, Macrohard 같은 시장 움직임과의 대비를 문서에 넣는다.

### 3.2 목표: 1인 = 100인 생산성

| 구분 | 설명 |
|------|------|
| **비전** | 한 사람이 서브 에이전트와 업무 흐름을 정의해서, 100명 규모 조직이 하던 일을 처리할 수 있게 한다. |
| **역할** | 서브 에이전트 = 팀원, 앱 = 부서 도구, 캔버스 = 공유 워크스페이스. |
| **결과** | "1인 기업이 100인 기업의 생산성을 대체한다"는 흐름. 소비자 도구가 아니라 **1인 기업 인프라**이다. |

### 3.3 SSOTA에서의 구현 구조

이미 아키텍처에 설계된 대로, "1인 = 100인"은 다음 구조로 실현된다.

```
[나 (1명)]
│
├── Sophie (메인 에이전트) = "비서실장"
│   ├── Explore 서브 에이전트 = "리서치 인턴"
│   ├── Research 서브 에이전트 = "리서치 팀장"
│   ├── Visualize 서브 에이전트 = "디자인 팀"
│   ├── Browser 서브 에이전트 = "현장 조사원"
│   └── Canvas 서브 에이전트 = "정리 담당"
│
├── 커스텀 서브 에이전트 (Phase 4) = "나만의 전문 팀원"
│   ├── "마케팅 리서처" = 마케팅 팀
│   ├── "경쟁사 분석가" = 전략 팀
│   └── "콘텐츠 제작자" = 콘텐츠 팀
│
├── 앱 (Phase 3–5) = "부서의 도구"
│   ├── SSOTA Crawl = 데이터 수집 부서
│   ├── SSOTA Image = 디자인 부서
│   ├── SSOTA Slide = 프레젠테이션 부서
│   └── 커뮤니티 앱 = 외주/파트너
│
└── 캔버스 = "공유 오피스"
    ├── 페이지 = 프로젝트별 회의실
    ├── 블록 = 작업 결과물 (영구 보존)
    └── 엣지 = 업무 간 관계
```

**업무 흐름 정의(Skill)**가 핵심이다. Phase 4에서 유저가 커스텀 서브 에이전트를 만들 때, 예를 들어:

```
"경쟁사 분석" Skill:
├── 1. 경쟁사 URL 수집 (Crawl App)
├── 2. 각 사이트 가격/기능 추출 (extractJSON)
├── 3. 비교 분석 (LLM)
├── 4. 리포트 작성 (Canvasdown)
└── 5. 슬라이드 생성 (Slide App)

→ 한 번 정의해두면, "삼성전자 경쟁사 분석해줘" 한 마디로 전체 파이프라인이 실행됨.
→ 100명 회사의 "전략팀이 하는 일"을 1인이 서브 에이전트 + 스킬 + 앱 조합으로 수행.
```

### 3.4 Macrohard vs SSOTA: 같은 목표, 다른 접근

Elon Musk의 Macrohard는 "인간 직원 제로, AI가 회사를 운영"하는 방향이다.  
SSOTA는 "사람을 빼는 것"이 아니라 **"한 사람에게 AI 팀을 주는 것"**이다.

| | Macrohard | SSOTA |
|--|-----------|--------|
| **의사결정** | AI가 자율적으로 | **사람이** 판단하고 지시 |
| **조직 구조** | AI 에이전트 간 위계 | 사람 → 메인 에이전트 → 서브 에이전트 |
| **목표** | 인간 조직을 에뮬레이션 (회사 − 사람 + AI) | 개인의 생산성을 조직 수준으로 (사람 + AI 팀 = 1인 회사) |
| **결과** | 사람 없는 회사 | **사람이 곧 회사** |

한 줄로 정리하면:

```
Macrohard:  회사 − 사람 + AI = AI 회사
SSOTA:      사람 + AI 팀 + AI 도구 = 1인 회사
```

투자자에게는 이렇게 말할 수 있다.

> "Macrohard와 SSOTA는 **같은 질문**에서 출발합니다:  
> **'AI 에이전트가 회사 수준의 일을 할 수 있다면, 조직은 어떻게 바뀌는가?'**
>
> Macrohard의 답: 사람을 빼고 AI로 채운다. AI 회사.  
> SSOTA의 답: 한 사람에게 AI 팀을 준다. **모든 사람이 회사가 된다.**
>
> 어느 쪽이 더 큰 시장인가?  
> - Macrohard: 기존 회사를 AI로 대체 → 기업 수만큼의 시장  
> - SSOTA: 모든 개인을 1인 기업으로 → **개인 수만큼의 시장**"

### 3.5 역사적 비유 보정: PC는 결국 기업의 인프라가 되었다

"메인프레임 vs PC" 비유를 유지하되, PC는 소비자 도구로 시작했지만 **결국 기업의 인프라**가 됐다는 점을 강조한다.

```
1980년대:
├── IBM 메인프레임 = 회사가 쓰는 컴퓨터 (Macrohard에 대응)
├── Apple PC = 개인이 쓰는 컴퓨터
│   └── PC 대중화 이후, 개인이 DTP·스프레드시트로 "전문 부서가 하던 일"을 혼자 수행
│   └── 1인 디자인 스튜디오, 1인 회계사무소, 1인 출판사 탄생
│   └── PC는 "소비자 도구"로 시작했지만, **결국 기업의 인프라**가 됨 (개인→1인 기업→기업 전반)
│
2025년:
├── Macrohard = AI가 운영하는 회사 (조직 대체)
├── SSOTA = 개인의 AI 컴퓨터
│   └── 서브 에이전트 = 나의 팀원들
│   └── 앱 = 나의 부서 도구들
│   └── 업무 흐름(Skill) = 나의 표준 프로세스
│   └── 결과: 1인이 100인의 생산성 = **1인 기업 인프라** (그 다음엔 기업 인프라로 확장 가능)
```

### 3.6 시장 지형도

```
[AI 에이전트가 조직 수준의 업무를 수행한다 — 시장 합의 형성 중]

        조직을 대체                          개인을 증강 → 개인이 조직이 됨
──────────────────────         ──────────────────────────────
Macrohard: AI 회사              SSOTA: 1인이 100인
Devin: AI 엔지니어
Factory AI: AI 팩토리

"사람 없는 회사"                  "모든 사람이 회사"

B2B (기존 기업 대체)              B2everyone (모든 개인이 기업가)
TAM: 기업 수                     TAM: 지식노동자 수
```

### 3.7 투자자용 핵심 논점

> "Macrohard가 성공하든 실패하든, **AI 에이전트가 회사 수준의 업무를 수행할 수 있다**는 합의가 생기고 있습니다.
>
> 그 파워가 존재한다면 두 가지 질문이 있습니다.  
> 1. 그 파워로 **기존 회사를 대체**할 것인가? → Macrohard의 베팅  
> 2. 그 파워를 **개인에게 줘서 모든 사람을 기업가로 만들** 것인가? → **SSOTA의 베팅**
>
> 역사적으로, 기술을 소수에 집중시키기보다 **대중에게 분산**시키는 쪽이 더 큰 시장을 만들어 왔습니다.  
> 메인프레임보다 PC가, 전용 회선보다 인터넷이, 기업 서버보다 클라우드가.
>
> SSOTA는 에이전트의 파워를 **분산**시킵니다. 모든 개인에게.  
> 그래서 SSOTA는 소비자 사이드에만 있는 게 아니라, **1인이 100인 기업의 생산성을 갖게 하는 인프라**입니다."

## 4. 컨텍스트 레이어와 사람 중심 설계

### 4.1 피터 틸의 질문: 버티컬 AI vs 통합 컨텍스트

> **"모든 사람들이 동의하지만 당신은 동의하지 않는 관점은 무엇인가요?"** — 피터 틸

**컨센서스 (많은 사람이 동의):**  
코딩 에이전트로 앱과 서비스를 만들기 쉬워졌기 때문에 **버티컬 AI 서비스**가 잘 될 것이다.

**반대 관점 (SSOTA의 베팅):**  
컨텍스트가 통합되지 않은 **독립된 버티컬 AI 서비스는 살아남지 못한다.**  
각 버티컬 서비스는 자기 도메인 컨텍스트만 안다. 유저의 "전체 그림"을 아는 곳이 없다.  
그래서 필요한 것은, 버티컬 서비스들이 **놀 수 있는 통합된 컨텍스트 플레이그라운드(레이어)**를 깔아주는 것이다.

**결론:**  
결국 다시 **버티컬한 플레이에서 독점의 새로운 시대**가 열린다.  
**컨텍스트 레이어**(PC 시대의 OS 레이어에 해당)를 독점하는 자가 승리한다.

### 4.2 컨텍스트 레이어 vs OS 레이어: 스택 비교

PC 시대와 AI 에이전트 시대의 스택을 나란히 보면, SSOTA가 노리는 레이어가 명확해진다.

```
[PC 시대]
├── 하드웨어 (CPU, 메모리)
├── OS 레이어 ← 독점 포인트 (Windows, macOS)
│   └── 파일 시스템, GUI, 앱 실행 환경, 프로세스 관리
├── 앱 레이어 (Word, Excel, Photoshop)
└── 유저

[AI 에이전트 시대]
├── LLM (OpenAI, Anthropic, Google) ← "CPU"에 해당
├── 컨텍스트 레이어 ← 독점 포인트 (SSOTA가 노리는 곳)
│   └── 유저의 데이터·관계·업무 흐름·에이전트 컨텍스트 통합
│   └── 에이전트와 앱이 "놀 수 있는" 통합 플레이그라운드
├── 앱 레이어 (버티컬 AI 서비스, SSOTA 앱들)
└── 유저
```

PC 시대에 OS가 앱의 "놀이터"였던 것처럼, AI 시대에는 **컨텍스트 레이어**가 에이전트와 앱의 놀이터다.  
LLM을 만드는 곳은 "CPU 제조사"이고, **컨텍스트 레이어를 만드는 곳이 "OS 제조사"**가 된다.

### 4.3 사람의 사고 구조와 SSOTA: 그래프 vs 트리

가장 기반 레이어에는 **사람의 사고에 대한 이해**를 바탕으로 하는 **사람 중심(human-centric)** 서비스가 있어야 한다.  
에이전트 중심(agent-centric)이기도 하지만, **사람의 사고에 가장 가깝고, 사람의 사고를 더욱 폭발시킬 수 있는 형태**가 필요하다.

**사람의 사고는 그래프다.**  
우리의 생각·개념 덩어리들은 하나에 매어 있지 않다. 여러 개의 생각들과 **관계**를 맺는다.  
그러나 기존 PC의 레이어는 **1차원적인 부모–자식 관계의 데이터 저장 방식(트리)**만 가능하다.  
폴더 안에 파일, 그 파일은 다른 폴더의 파일과 "관계"를 시스템 수준에서 표현할 수 없다.  
사람 머릿속에서는 연결되어 있지만, 시스템에서는 분리되어 있다.

**SSOTA의 방향:**  
이를 뛰어넘어, **사람의 사고에 가장 가깝고**, 에이전트와 함께 이 구조를 이해할 수 있는 시스템으로 발전시킨다.

```
[사람의 사고 — 그래프]
  "경쟁사 분석" ─── "가격 전략" ─── "내 제품 포지셔닝"
       │                │                    │
  "시장 트렌드" ──── "고객 니즈" ──── "마케팅 기획"
       │                                     │
  "기술 동향" ─────────────────────── "로드맵"

  → 비선형. 부모–자식이 아니라 peer-to-peer. 여러 개념이 서로 관계를 맺음.

[기존 PC — 트리]
  📁 프로젝트/
  ├── 📁 리서치/
  │   ├── 경쟁사.docx
  │   └── 시장분석.xlsx
  ├── 📁 기획/
  │   └── 전략.pptx
  └── 📁 마케팅/
      └── 캠페인.doc

  → "경쟁사.docx"와 "전략.pptx"의 관계를 시스템이 표현할 수 없음.

[SSOTA 캔버스 — 그래프]
  [경쟁사 분석 블록] ──edge──→ [가격 비교 블록]
         │                            │
       edge                         edge
         │                            │
  [시장 트렌드 블록] ──edge──→ [전략 기획 블록]

  → 블록(개념) + 엣지(관계). 사람의 사고 구조와 동일.
  → 에이전트도 이 관계를 이해하고 활용할 수 있음.
```

## 5. 투자자 관점: 매킨토시 모먼트

### 5.1 역사적 맥락: 컴퓨터의 대중화

```
[1970s] 홈브루 컴퓨터 클럽
  └── 컴퓨터 = 애호가의 보드. 조립·납땜·기계어. "쓸 수 있는 사람"만 씀.
  └── 가치를 아는 사람은 있지만, 대중에게는 불가능한 도구.

[1984] 매킨토시 — GUI의 등장
  └── 명령어를 몰라도 된다. 마우스로 클릭하면 된다.
  └── 핵심: 기술의 본질은 바뀌지 않았다. "인터페이스"가 바뀌었다.
  └── 컴퓨터의 가치가 대중에게 열린 순간.

[1990s–2000s] Personal Computing 시대
  └── 모든 가정에 PC. 모든 업무에 PC.
  └── 앱 생태계, 인터넷, 그래픽, 멀티미디어.
```

### 5.2 지금의 AI 에이전트 = 1970s 보드

```
[2024–2025] Claude Code, Cursor — CLI/IDE의 시대
  └── AI 에이전트 = 얼리어답터의 도구.
  └── CLI, IDE, MCP, 프롬프트 엔지니어링을 알아야 함.
  └── "쓸 수 있는 사람"만 쓰고 있음.
  └── 가치를 아는 사람은 많아지고 있지만, 대중에게는 여전히 진입장벽.

  홈브루 컴퓨터 클럽의 보드와 같다:
  - 보드 = 강력하지만, "조립할 수 있는 사람"만 쓸 수 있었다.
  - 코딩 에이전트 = 강력하지만, "CLI/MCP를 아는 사람"만 쓸 수 있다.
```

### 5.3 SSOTA = 매킨토시

```
[SSOTA] Personal Agentic Computing — GUI의 재탄생
  └── CLI/MCP를 몰라도 된다. 말하면 된다.
  └── 핵심: AI 에이전트의 본질은 바뀌지 않는다. "인터페이스"가 바뀐다.
  └── 에이전트의 가치가 대중에게 열리는 순간.
```

### 5.4 매킨토시와의 정밀 대응

| 매킨토시 (1984) | SSOTA |
|-----------------|-------|
| 명령어(CLI) → 마우스 클릭(GUI) | CLI/IDE/MCP → 자연어 + 캔버스 |
| 파일 시스템 → 데스크톱 메타포 | 파일/채팅 로그 → 캔버스(공간적 배치 + 관계) |
| 앱 설치 → 새로운 능력 추가 | 앱 설치 → 새로운 블록 타입 + 도구 추가 |
| 모든 가정에 PC | 모든 지식노동자에게 AI 에이전트 |
| "나머지 사람들을 위한 컴퓨터" | "나머지 사람들을 위한 AI 에이전트" |

### 5.5 투자자에게 전달할 3가지 핵심

**1. 시장 전환의 역사적 패턴과 같다**

> 컴퓨터가 홈브루 클럽에서 매킨토시로 넘어간 것과 같은 전환.
> Claude Code/Cursor는 강력하지만, "조립할 수 있는 사람"만 쓴다.
> SSOTA는 AI 에이전트를 "나머지 사람들"에게 여는 인터페이스.

**2. 기술이 아니라 인터페이스가 시장을 만든다**

> CPU를 만든 인텔이 아니라, GUI를 만든 애플이 PC 시장을 만들었다.
> LLM을 만든 OpenAI/Anthropic이 아니라, **에이전트의 인터페이스**를 만드는 곳이 시장을 만든다.
> SSOTA는 AI 에이전트 시대의 인터페이스 레이어.

**3. 장기 비전: Agentic OS의 MVP**

> 현재: 캔버스 + 에이전트 + 블록 시스템
> 다음: 앱 생태계 + 앱 마켓 + 커스텀 서브 에이전트
> 장기: 에이전트 네이티브 OS — 데이터·도구·관계·컨텍스트가 통합된 컴퓨팅 환경
>
> 매킨토시도 처음에는 GUI + 몇 개의 앱이었다.
> 운영체제는 생태계와 함께 자란다. SSOTA는 그 OS의 MVP이다.

### 5.6 Claude Code / Cursor와의 포지셔닝

| | Claude Code / Cursor | SSOTA |
|---|---|---|
| **사용자** | 개발자, 얼리어답터 | **모든 지식노동자** |
| **인터페이스** | CLI, IDE, 터미널 | 캔버스 + 자연어 |
| **결과물** | 코드, 파일 | 블록 (시각화 + 관계 + 영속) |
| **진입장벽** | MCP, 프롬프트, 코딩 개념 | 없음 (URL 드롭 + 말하기) |
| **비유** | 홈브루 컴퓨터 보드 | **매킨토시** |
| **가치** | 기술적 파워 | 기술적 파워 + **대중 접근성** |

경쟁이 아니라 **시장 확장**이다.  
Claude Code/Cursor가 개발자를 위한 파워 도구라면, SSOTA는 그 파워를 **나머지 95%의 사람들**에게 전달하는 인터페이스.

## 6. 유저 관점: 말하면 다 되는 AI 컴퓨터

### 6.1 핵심 메시지

> **"다른 도구를 배울 필요가 없다."**

AI 에이전트(Claude Code, Cursor)를 쓰려면 배워야 하는 것들:

| 배워야 하는 것 | 그게 뭔데 | 왜 배워야 하는데 |
|---------------|----------|-----------------|
| CLI (터미널) | 검은 화면에 명령어 치는 것 | 에이전트 실행/결과 확인 |
| IDE | 코드 편집기 | 파일 관리/코드 수정 |
| MCP | AI가 외부 도구를 쓰는 프로토콜 | Firecrawl, GitHub 등 연결 |
| 프롬프트 엔지니어링 | AI에게 정확하게 지시하는 기술 | 원하는 결과를 얻기 위해 |
| 코딩 개념 | 변수, 함수, API... | 결과를 이해하고 수정 |

**이것들은 핵심이 아니다.**

유저가 진짜 하고 싶은 것은:
- 경쟁사 가격 비교
- 시장 리서치 정리
- 기획안을 슬라이드로 만들기
- 데이터 수집·분석

CLI, IDE, MCP는 **목적이 아니라 수단**인데, 지금은 그 수단을 배우는 데 시간이 든다.

### 6.2 SSOTA가 유저에게 하는 약속

```
❌ CLI를 배울 필요 없다.
❌ IDE를 설치할 필요 없다.
❌ MCP가 뭔지 알 필요 없다.
❌ 코드를 읽을 필요 없다.

✅ URL을 드롭하면 된다.
✅ 하고 싶은 걸 말하면 된다.
✅ 결과는 캔버스에 보인다.
✅ 다음에 와도 다 남아있다.
```

### 6.3 유저 메시지 — 레벨별

**Level 2 (리서치·기획):**

> **"내 리서치 비서. URL 넣고 말하면, 데이터 수집부터 분석까지."**
>
> 경쟁사 사이트 3개 넣고 "요금제 비교해줘" 한 마디.
> 코드 없이. 스크립트 없이. MCP 없이.
> 데이터가 정리되고, 비교표가 만들어지고, 인사이트가 정리된다.
> 다 캔버스에 남는다. 다음에 이어서 하면 된다.

**Level 3 (제작):**

> **"말하면 다 되는 AI 컴퓨터."**
>
> 리서치도. 기획도. 슬라이드도. 견적서도.
> 생각만 정리하면, 결과물이 나온다.
> 그리고 그 과정이 전부 캔버스에 남는다.

### 6.4 유저 관점에서 Claude Code/Cursor와의 차이

유저에게 경쟁 제품 비교는 중요하지 않다.  
중요한 건 **"내가 뭘 안 배워도 되느냐"**이다.

| 하고 싶은 것 | Claude Code / Cursor | SSOTA |
|-------------|---------------------|-------|
| 경쟁사 사이트에서 가격 데이터 수집 | MCP 설치 → firecrawl 연결 → 스크립트 실행 | **URL 드롭 → "가격 뽑아줘"** |
| 수집한 데이터 비교 분석 | 결과 파일 읽기 → 프롬프트로 분석 요청 | **"비교표 만들어줘"** |
| 분석 결과를 슬라이드로 | 슬라이드 라이브러리 코드 작성 → 빌드 → 확인 | **"슬라이드 만들어줘"** |
| 다음에 이어서 작업 | 파일 경로 기억 → 컨텍스트 다시 주입 | **캔버스 열면 다 있음** |

| 가장 짧게 | 생각 → 결과물. 코딩 제로 |
| 유저에게 | 기획안을 쓰면 슬라이드가 나온다. 리서치를 시키면 보고서가 나온다. 전부 한 공간에서 |
| 투자자에게 | 매킨토시 모먼트. 에이전트의 파워를 앱 생태계로 확장하는 Personal Agentic Computing |

### 8.4 경쟁 포지셔닝

| 맥락 | 한 문장 |
|------|---------|
| vs Claude Code | Claude Code는 파워 유저의 CLI 도구. SSOTA는 나머지 95%를 위한 인터페이스 |
| vs Cursor | Cursor가 코딩 에이전트의 IDE라면, SSOTA는 모든 업무를 위한 에이전트 캔버스 |
| vs Perplexity | Perplexity는 검색의 AI화. SSOTA는 업무 전체(리서치→기획→제작)의 AI화 |
| vs Notion AI | Notion AI는 문서 안의 AI. SSOTA는 문서·데이터·앱이 통합된 에이전트 컴퓨팅 환경 |

### 8.5 1인 기업 = 100인 / Macrohard 대비

| 맥락 | 한 문장 |
|------|---------|
| 포지션 | SSOTA는 소비자 도구가 아니라, 1인이 100인 기업의 생산성을 갖게 하는 **1인 기업 인프라** |
| vs Macrohard | Macrohard는 회사 − 사람 + AI. SSOTA는 사람 + AI 팀 + AI 도구 = 1인 회사. 같은 질문(조직의 미래), 다른 답(대체 vs 증강) |
| 투자자용 | AI 에이전트가 회사 수준의 일을 한다면, 그 파워를 기업에 집중할 것인가(Macrohard) 개인에게 분산할 것인가(SSOTA). 분산이 더 큰 시장 |
