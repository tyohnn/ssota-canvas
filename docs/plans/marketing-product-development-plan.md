# 쏘타 마케팅·제품개발 계획

> 본 문서는 `inbox.plan.md` 대화 내용을 기반으로 정리한 마케팅 및 제품개발 전략 문서입니다.

---

## 1. 비전 및 방향

### 궁극적 비전

쏘타의 궁극적 방향은 **비개발자를 위한 Claude Code GUI 버전**이다.

- Claude Code는 코딩 에이전트로 시작했으나, 코드는 디지털 세상의 원형이므로 PDF, 상세페이지, 카드뉴스, 디자인, 앱, 비디오 등 다양한 결과물을 생성 가능
- 사실상 범용 업무 에이전트로 활용되고 있음
- 그러나 UX가 터미널·코드 에디터 형태라 비개발자에게 진입 장벽이 높음

### 쏘타의 완성된 형태

- **캔버스** = 컨텍스트 공용 공간 (파일트리 역할)
- **Claude Code의 파일**을 읽고 검색하는 툴 제공
- **코딩 에이전트** 별도 제공
- 사용자 플로우:
  1. 업무 맥락을 메시지처럼 쉽게 올림 (링크, 첨부파일, 노트 등)
  2. 말로 맥락 전달
  3. 인풋/맥락이 캔버스에 저장됨
  4. 쏘타 에이전트가 범용 툴(웹검색, 코딩 에이전트, 앱 연동)로 결과물 생성

## 2. 현재 제품 포지셔닝

### 메시지 선택: "복붙 지옥"

- **"Claude Code 어렵지 않으세요?"** 대신 **"복붙 지옥"**으로 소구점 확정
- 현재 제품이 실제로 하는 것과 메시지가 정합성 있음

| 구분 | 현재 상태 |
|------|----------|
| 맥락 수집/정리/AI가 읽기 | ✅ |
| 범용 에이전트 실행·결과물 생성 | ❌ |

초기에는 **메시지와 제품 기능의 정합성**이 가장 중요하다.

### 현재 문제점

- 복붙 지옥을 건드리긴 했으나 **체감 와우가 약함**
- 사용자가 직접 캔버스에 링크를 추가해야 하는 마찰 존재
- 말만 맞고 체감이 약하면 전환이 나오지 않음

---

## 3. 리소스 배분 전략: 70 / 20 / 10

### 70% — 복붙 지옥 해결 체감 강화 (현재 약속 강화)

- Quick Capture Inbox
- 모바일 음성/메모/링크 캡처
- 브라우저 Send-to-SSOTA
- 자동 정리/분류/요약

### 20% — 결과물 와우 1개 (미래 비전 데모)

- 자료 올리고 한 문장 말하면 **PPT 초안 아웃라인** 생성
- 리서치 브리프/PRD 초안 생성
- 회의록 → 실행계획 문서

> 중요: "범용 에이전트 완성"이 아니라 **한 가지 결과물 플로우를 매끈하게** 만드는 것

### 10% — Claude Code GUI 방향의 기반 설계

- 툴 호출 로그/추적 UI 기초
- 작업 단계 표시 (계획→수집→작성)
- 캔버스 내 실행 trace 구조

---

## 4. 와우(Wow) 포인트 전략

### A. 입력 와우 (Capture Wow)

> "와 이거 넣는 게 진짜 편하네"

- 습관/재방문을 만듦
- 복붙 지옥 메시지와 직결
- 현재 제품 포지셔닝과 가장 잘 맞음

### B. 출력 와우 (Outcome Wow)

> "와 이걸 이렇게 바로 결과물로?"

- 공유/바이럴에 유리
- 미래 비전(Claude Code GUI)와 연결됨
- 구현 난이도와 품질 리스크가 큼

### 결론

- **현재 단계에서는 입력 와우(A)를 먼저 강화**
- 아직 사용자가 "문제가 해결되는 느낌"을 받기 전에 이탈할 가능성이 크므로

## 5. 복붙 지옥 소구 강화 "와우 기능" 우선순위

### 1순위: Quick Capture Inbox ⭐ (가장 추천)

| 항목 | 내용 |
|------|------|
| 핵심 아이디어 | 캔버스에 직접 들어가지 않아도 일단 보낼 수 있게 |
| 형태 | `ssota.ai/inbox` 빠른 입력 페이지, 링크/파일/텍스트/음성 |
| 와우 포인트 | 보내자마자 3~10초 내 제목 추출, 한 줄 요약, 소스 타입 분류, 관련 기존 자료 추천 |
| 핵심 메시지 | "넣는 순간 정리된다" |

### 2순위: 모바일 공유 (Share to SSOTA)

- 유튜브/브라우저/파일앱에서 공유 버튼 → "SSOTA로 보내기"
- 실제 복붙 행동을 대체
- 초기에는 웹 인박스 + 모바일 최적화로 시작, 이후 네이티브/확장 고려

### 3순위: 브라우저 확장 / 북마클릿 (Send to SSOTA)

- 현재 페이지 클릭 한 번으로 보내기
- 선택한 텍스트 + URL 함께 저장
- 리서치/기획 사용자에게 적합

### 4순위: 음성 메모 원탭 캡처 (모바일)

- 버튼 누르고 말하면 자동 전사 + 요약 + TODO/질문 분리

### 5순위: 자동 프로젝트 분류 / 추천 라우팅

- AI가 프로젝트 후보 추천
- "이 링크는 [신규 랜딩페이지], [시장조사], [브랜딩] 중 어디에 넣을까요?"

### 보류 (현재 시점)

- 자동 클립보드 감시 (프라이버시 이슈)
- 범용 앱 연동 무한 확장
- 고도화된 실시간 화면 추적

## 6. 결과물 와우 최소단위 MVP

### 추천 1: 소스 → 발표 초안 아웃라인

- **입력:** 링크/PDF/오디오
- **요청:** "이걸 바탕으로 10장 발표 구성"
- **출력:** 슬라이드 제목 리스트, 각 슬라이드 핵심 bullet, 근거 소스 참조, 발표 목적별 톤

### 추천 2: 소스 → 업무 실행 브리프

- **입력:** 회의녹음 + PDF + 링크
- **요청:** "다음 주 실행계획 만들어줘"
- **출력:** 요약, 결정사항, 미결 질문, 담당자/기한 placeholder, 다음 액션

### 추천 3: 소스 → 카드뉴스/상세페이지 초안 구조

- 섹션 구조, 메시지 흐름, 카피 초안, 필요한 비주얼 리스트

> "PPT 완성"보다 **"PPT 초안 생성"**으로 범위를 잘라서 시작 추천

## 7. 마케팅 메시지 사다리

### 지금 (현재 기능)

**"복붙 없이 업무 맥락을 모으고, AI가 읽게 만드는 공간"**

- 링크/PDF/오디오/유튜브 정리
- AI가 맥락 기반으로 답변

### 다음 (가까운 미래)

**"맥락에서 결과물 초안까지 만드는 업무공간"**

- 브리프/PPT/실행계획 초안 생성

### 미래 (궁극 방향)

**"비개발자를 위한 Claude Code GUI 같은 범용 업무 에이전트"**

- 툴 호출/코딩 에이전트/앱 연동/결과물 자동 제작

---

## 8. 브랜드·마케팅 리스크 (중요)

"Claude Code" 키워드는 마케팅적으로 강하나, 표현은 신중해야 함.

| 추천 톤 | 피해야 할 톤 |
|---------|--------------|
| "Claude Code 같은 경험을 비개발자도 쓸 수 있게" | 제휴/공식/호환을 과하게 암시하는 표현 |
| "코딩 에이전트의 강력함을 업무용 GUI로 풀어낸 방향" | |

비교 포지셔닝은 적절하나, 공식 관계처럼 보이는 표현은 리스크가 있다.

---

## 9. 우선순위 판단 지표

### 입력 와우 필요성 확인

- 가입 후 **첫 자료 추가율**
- 첫 자료 추가까지 걸리는 시간
- 1일 내 **2개 이상 자료 추가율**
- 7일 내 재방문해서 자료 추가하는 비율

→ 낮으면 **무조건 입력 UX 먼저**

### 출력 와우 필요성 확인

- 자료 넣고 AI 질문/요청까지 가는 비율
- 생성 결과를 복사/공유/내보내기 하는 비율
- "오 좋다" 반응 vs "그래서 뭐하지?" 반응

→ 낮으면 **결과물 플로우 강화**

## 10. 실행 순서 (2단계)

### Step 1 (지금): 복붙 지옥 체감 해결

**목표:** "넣는 게 편하다"를 느끼게

- Quick Capture Inbox (링크/파일/텍스트/음성)
- 모바일 우선 캡처 UX
- 전송 후 자동 요약 카드, 최근 프로젝트 추천

**마케팅 문구 강화:**
- "복붙 말고 그냥 보내세요"
- "보내면 자동으로 정리되고 AI가 이해합니다"

### Step 2 (바로 다음): 결과물 와우 1개

**목표:** "그래서 이게 업무에 쓸모 있네"를 보여주기

- 리서치 브리프 생성 또는 PPT 아웃라인 생성
- 완성본보다 **초안 생성 + 소스 연결**에 집중

## 11. 스킬 / 서브에이전트 / 쏘타 앱 계층

### 역할 매핑

| 계층 | 70/20/10 | 역할 |
|------|----------|------|
| Skills (사용자-facing) | 20% | 결과물 와우를 보여주는 가장 쉬운 수단 |
| Subagents (내부 오케스트레이션) | 10% | 스킬의 구현체, 사용자에게 숨김 |
| SSOTA Apps (에이전트 조작 가능한 앱) | 10% | 장기적 플랫폼 파워의 핵심 |

### 개발 순서

1. **Phase 1** — 내부 스킬화: 처리 로직 모듈화 (`extract_source`, `summarize_source`, `recommend_pages` 등)
2. **Phase 2** — 사용자-visible Skills 2~3개 공개 (회의록→실행계획, 발표 아웃라인, 요약 노트)
3. **Phase 3** — Subagent 개념 도입 (내부 오케스트레이션)
4. **Phase 4** — SSOTA Apps (아웃라인/브리프형 첫 앱)

### 주의사항

- **스킬**: 초기엔 2~3개만, 이름은 업무 중심으로
- **서브에이전트**: 내부 용어로 먼저 사용, 사용자에게는 "스킬"만 노출
- **앱**: 완성 툴보다 구조화 툴부터 (아웃라인/브리프 앱)
