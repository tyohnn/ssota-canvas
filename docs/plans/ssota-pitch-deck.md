## Slide 2. 배경: 코딩 에이전트가 가져온 변화

### 펀치라인

> **"코딩은 디지털 세계의 원형(原形)이다. 그 원형을 AI가 다루게 되면서, 모든 것이 바뀌었다."**

### 논리 흐름

Claude Code, Cursor 같은 코딩 에이전트가 미친 변화를 가져오고 있다.

```
┌─────────────────────────────────────────────────┐
│                                                 │
│  [코딩 에이전트의 등장]                             │
│                                                 │
│  코딩 = 디지털의 원형(原形)                         │
│  ─────────────────────────                      │
│  코드로 만들 수 있는 것:                            │
│                                                 │
│  📄 문서    📊 데이터 분석    🎨 이미지             │
│  🎬 영상    📑 슬라이드     ⚡ 미니앱              │
│  📋 견적서   🌐 웹사이트     🤖 자동화              │
│                                                 │
│  → AI가 코딩을 할 수 있게 되면서,                    │
│    "만들 수 있는 모든 것"을 만들 수 있는             │
│     범용 에이전트가 탄생.                           │
│                                                 │
│  개발은 언제나 장벽이었다.                           │
│  그 장벽이 사라지는 중이다.                          │
│                                                 │
└─────────────────────────────────────────────────┘
```

- 코딩이라는 행위 자체가 디지털에서의 원형적 능력이다. 문서, 이미지, 영상, 슬라이드, 웹사이트, 미니앱 — 디지털 결과물은 전부 코드로 만들어진다.
- AI가 이 원형을 다루게 되면서 "코딩을 넘어선 범용 에이전트"가 탄생했다. 코드를 짜는 것이 아니라, 코드를 통해 **모든 종류의 결과물**을 만들 수 있다.
- 개발자만 가능했던 것들이 열리고 있다. 이것은 미친 변화다.
- 사람들이 직접 자기만의 서비스를 만들고, 문서에서 영상, 이미지, 슬라이드, 자신에게 맞는 미니앱을 만드는 시대가 시작됐다.

## Slide 3. 문제: 그러나 쓸 수 있는 사람이 없다

### 펀치라인

> **"가장 강력한 도구가, 가장 쓰기 어렵다."**

### 논리 흐름

```
┌─────────────────────────────────────────────────┐
│                                                 │
│  [Claude Code / Cursor를 쓰려면?]                │
│                                                 │
│  ✗ CLI (검은 화면에 명령어)                        │
│  ✗ IDE (코드 편집기 설치·설정)                      │
│  ✗ MCP (AI↔외부 도구 연결 프로토콜)                 │
│  ✗ 프로젝트 구조 (폴더, 파일, 빌드)                 │
│  ✗ 프롬프트 엔지니어링                             │
│  ✗ 코딩 개념 (변수, 함수, API)                     │
│                                                 │
│  ─────────────────────────────────              │
│                                                 │
│  열광하는 사람 = 극소수 얼리어답터                    │
│  UX/UI가 폭력적이다.                               │
│  새로운 개념이 너무 많다.                            │
│                                                 │
└─────────────────────────────────────────────────┘
```

- Claude Code와 Cursor에 열광하는 사람들은 매우 소수의 얼리어답터다.
- 사용하기 위한 진입 장벽이 극도로 높다. IDE 설치, CLI 사용, 프로젝트 생성, MCP 연결 — 각각이 하나의 학습 과정이다.
- UX/UI가 폭력적이다. 개발자의 도구를 그대로 쓰라고 하는 것이다.
- 에이전트의 파워는 증명됐다. **그러나 쓸 수 있는 사람이 없다.**

## Slide 4. 질문: 5년 뒤에도 이렇게 쓸까?

### 펀치라인

> **"우리 엄마가 Claude Code를 깔고 MCP를 설정할까? 절대 아니다."**

### 논리 흐름

```
┌─────────────────────────────────────────────────┐
│                                                 │
│  과연 5년 뒤, 10년 뒤에                            │
│  사람들이 에이전트와 소통하는 방식이                   │
│  CLI와 IDE일까?                                   │
│                                                 │
│  ┌───────────────────────────────────┐          │
│  │                                   │          │
│  │  > claude "MCP 설정해줘"           │          │
│  │  > npm install firecrawl-mcp      │          │
│  │  > cursor .                       │          │
│  │                                   │          │
│  │  이것이 미래의 인터페이스인가?        │          │
│  │                                   │          │
│  └───────────────────────────────────┘          │
│                                                 │
│                 절 대  아 니 다.                    │
│                                                 │
│  사람들이 에이전트를 쓰기 위해                       │
│  터미널을 배워야 할 이유가 없다.                      │
│                                                 │
└─────────────────────────────────────────────────┘
```

- 5년 뒤, 10년 뒤에 사람들이 에이전트와 소통하는 방식이 CLI일까?
- 에이전트와 소통하기 위해 정말 Claude Code를 다운로드하고 MCP를 배워야 할까?
- **우리 엄마가 할 수 있을까?** 절대 아니다.
- 그럼 미래의 인터페이스는 어떤 모습이어야 하는가? → 이 질문에 답하기 위해 과거를 본다.

## Slide 5. 역사: 매킨토시 이전의 컴퓨터

### 펀치라인

> **"1984년 이전, 컴퓨터는 '쓸 수 있는 사람만 쓰는 도구'였다."**

### 논리 흐름

```
┌─────────────────────────────────────────────────┐
│                                                 │
│  [1970s — 홈브루 컴퓨터 클럽]                      │
│                                                 │
│  ┌─────────────────────────────────┐            │
│  │ > LOAD "PROGRAM",8,1           │            │
│  │ > RUN                          │            │
│  │ SYNTAX ERROR IN LINE 320       │            │
│  │ > _                            │            │
│  └─────────────────────────────────┘            │
│                                                 │
│  • 조립·납땜·기계어                               │
│  • 터미널 명령어를 알아야 함                        │
│  • 키보드와 마우스도 지금의 형태가 아님               │
│  • 컴퓨터의 능력을 아는 사람들은 열광                 │
│  • 기업에서 먼저 도입                              │
│  • 그러나 대중에게는 갈 수 없었음                    │
│                                                 │
│  가치를 아는 사람은 있었다.                          │
│  그러나 가치를 쓸 수 있는 사람은 없었다.               │
│                                                 │
└─────────────────────────────────────────────────┘
```

- 매킨토시가 나오기 전의 컴퓨터는 어려웠다.
- 터미널을 알아야 했고, 키보드와 마우스도 지금과 달랐다.
- 컴퓨터의 능력을 아는 사람들은 열광했고, 기업에서 먼저 도입했다.
- 하지만 대중에게는 갈 수 없었다. "가치를 아는 것"과 "가치를 쓸 수 있는 것"은 달랐다.
- **지금의 AI 에이전트 = 그때의 컴퓨터.**

## Slide 6. 전환: 매킨토시 모먼트

### 펀치라인

> **"기술은 바뀌지 않았다. 인터페이스가 바뀌었다. 그리고 세상이 바뀌었다."**

### 논리 흐름

```
┌─────────────────────────────────────────────────┐
│                                                 │
│  [1984 — Macintosh]                             │
│                                                 │
│  ┌─────────────────────────────────┐            │
│  │  ┌──────┐  ┌──────┐  ┌──────┐ │            │
│  │  │ File │  │ Edit │  │ View │ │            │
│  │  └──────┘  └──────┘  └──────┘ │            │
│  │                                │            │
│  │  📁 Documents    🗑️ Trash     │            │
│  │  📁 Applications              │            │
│  │                                │            │
│  │  명령어 몰라도 된다.             │            │
│  │  마우스로 클릭하면 된다.          │            │
│  └─────────────────────────────────┘            │
│                                                 │
│  CPU는 같다. 메모리는 같다.                        │
│  바뀐 것은 "인터페이스" 하나.                       │
│  그리고 컴퓨터가 대중에게 열렸다.                    │
│                                                 │
│  → 결과: Personal Computing 시대                  │
│  → 모든 가정에 PC. 40년 간의 기업 인프라.            │
│                                                 │
└─────────────────────────────────────────────────┘
```

- 스티브 잡스와 워즈니악의 매킨토시가 이 벽을 깼다.
- CPU가 바뀐 게 아니다. 메모리가 바뀐 게 아니다. **인터페이스가 바뀌었다.** GUI의 등장.
- 명령어를 몰라도 된다. 마우스로 클릭하면 된다. 그리고 컴퓨터의 가치가 대중에게 열렸다.
- 이후 PC는 소비자 도구에서 시작해 **결국 기업의 인프라**가 됐다.
- 우리 엄마도 컴퓨터를 쓸 수 있게 된 것.

## Slide 7. 레이어 비교: 그때와 지금

### 펀치라인

> **"역사는 반복된다. 레이어까지."**

### 논리 흐름

```
┌─────────────────────────────────────────────────┐
│                                                 │
│  [PC 시대]                 [AI 에이전트 시대]       │
│  ──────────               ────────────────       │
│                                                 │
│  하드웨어                   LLM                   │
│  (CPU, 메모리)             (OpenAI, Anthropic)    │
│       │                        │                │
│  OS 레이어 ◄─ 독점         컨텍스트 레이어 ◄─ 독점  │
│  (Windows, macOS)          (?????)              │
│  GUI + 파일시스템 +         데이터 + 관계 +         │
│  앱 실행 환경               에이전트 통합 환경       │
│       │                        │                │
│  앱 레이어                  앱 레이어               │
│  (Word, Excel,             (버티컬 AI,            │
│   Photoshop)               에이전틱 앱)            │
│       │                        │                │
│  유저                       유저                   │
│                                                 │
│  ─────────────────────────────────              │
│  CPU를 만든 인텔이 아니라                           │
│  OS를 만든 MS/Apple이 승리했다.                     │
│                                                 │
│  LLM을 만든 OpenAI가 아니라                        │
│  컨텍스트 레이어를 만드는 곳이 승리한다.               │
│                                                 │
└─────────────────────────────────────────────────┘
```

- PC 시대의 스택: 하드웨어 → OS 레이어(독점 포인트) → 앱 → 유저.
- AI 시대의 스택: LLM → **컨텍스트 레이어**(독점 포인트) → 앱 → 유저.
- PC 시대에 CPU를 만든 인텔이 아니라, GUI 운영체제를 만든 Microsoft/Apple이 시장을 지배했다.
- AI 시대에 LLM을 만든 OpenAI/Anthropic이 아니라, **컨텍스트 레이어를 만드는 곳**이 시장을 지배한다.
- 매킨토시가 GUI라는 인터페이스 + 앱 실행 환경을 만들었듯이, SSOTA는 **자연어 인터페이스 + 컨텍스트 통합 환경**을 만든다.
- 이것이 우리가 만들려는 것이다.

## Slide 8. 선언: Personal Agentic Computing

### 펀치라인

> **"매킨토시가 Personal Computing을 열었듯, SSOTA가 Personal Agentic Computing을 연다."**

### 논리 흐름

```
┌─────────────────────────────────────────────────┐
│                                                 │
│         Personal Agentic Computing              │
│         ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─               │
│                                                 │
│  [1984]                    [2025]               │
│  ─────                    ──────                │
│  CLI → GUI                 CLI/IDE/MCP → GUI/캔버스   │
│  명령어 → 클릭              코드 → 자연어            │
│  파일 → 데스크톱            채팅 로그 → 공간         │
│  앱 설치 → 새 능력          앱 설치 → 새 블록+도구   │
│                                                 │
│  "나머지 사람들을 위한       "나머지 사람들을 위한     │
│   컴퓨터"                    AI 에이전트"            │
│                                                 │
│  ─────────────────────────────────              │
│                                                 │
│  같은 전환. 같은 패턴. 같은 기회.                    │
│  에이전트의 파워를 대중에게 여는 인터페이스.            │
│                                                 │
└─────────────────────────────────────────────────┘
```

- Personal Computing = 컴퓨터를 개인에게.
- **Personal Agentic Computing** = AI 에이전트를 개인에게.
- CLI/IDE/MCP를 몰라도 된다. 말하면 된다. 결과는 캔버스에 남는다.
- 같은 전환의 패턴. 같은 기회의 크기.

│                                                 │
│  MCP가 필요 없다. 인프라가 있으니까.                 │

- 지금의 에이전트가 외부 도구를 쓰려면 MCP라는 프로토콜을 하나하나 연결해야 한다.

- **유저의 전체 그림을 아는 곳이 없다.** 이것이 근본 문제다.
- SSOTA는 **컨텍스트 레이어**를 만든다. 유저의 모든 데이터·관계·업무 흐름이 이 레이어 위에 통합되어 있고, 에이전트와 앱은 이 위에서 작동한다.

┌─────────────────────────────────────────────────┐

- 이를 통해 인간의 사고 또한 부스팅시킨다.

## Slide 16. 사업: 1인 = 100인 기업 인프라

### 펀치라인

> **"Macrohard는 사람을 뺀다. SSOTA는 사람에게 팀을 준다. 어느 쪽이 더 큰 시장인가?"**

### 논리 흐름

```
┌─────────────────────────────────────────────────┐
│                                                 │
│  [같은 질문, 다른 답]                               │
│                                                 │
│  "AI가 회사 수준의 일을 할 수 있다면,                 │
│   조직은 어떻게 바뀌는가?"                           │
│                                                 │
│  Macrohard            SSOTA                     │
│  ─────────            ──────                    │
│  회사 − 사람 + AI      사람 + AI팀 + AI도구          │
│  = AI 회사             = 1인 회사                   │
│                                                 │
│  "사람 없는 회사"       "모든 사람이 회사"             │
│                                                 │
│  TAM: 기업 수           TAM: 지식노동자 수           │
│  B2B                   B2everyone                │
│                                                 │
│  ─────────────────────────────────              │
│                                                 │
│  [사업 확장]                                       │
│                                                 │
│  1인 = 100인 생산성을 가능하게 하는 인프라             │
│  ├── 인프라 사업 (컨텍스트 레이어 플랫폼)             │
│  ├── 사무실 임대 사업 (워크스페이스 = 디지털 오피스)    │
│  └── 앱 마켓 사업 (에이전틱 앱 생태계)               │
│                                                 │
│  역사적 패턴:                                      │
│  분산이 집중보다 더 큰 시장을 만든다.                  │
│  메인프레임 < PC. 전용회선 < 인터넷. 기업서버 < 클라우드│
│                                                 │
└─────────────────────────────────────────────────┘
```

- Macrohard와 SSOTA는 같은 질문에서 출발한다: "AI가 회사 수준의 일을 할 수 있다면?"
- Macrohard의 답: 사람을 빼고 AI로 채운다. **AI 회사.**
- SSOTA의 답: 한 사람에게 AI 팀을 준다. **모든 사람이 회사.**
- TAM: Macrohard = 기존 기업 수 (B2B). SSOTA = 지식노동자 수 (B2everyone).
- 역사적으로, 기술을 소수에 집중시키기보다 **대중에게 분산**시키는 쪽이 더 큰 시장을 만들어 왔다.
- 이를 통해 사람 1명이 100명 기업의 생산성을 내는 **인간 x AI 협업 기업**이 가능하도록:
  - **인프라 사업**: 컨텍스트 레이어 플랫폼
  - **사무실 임대 사업**: 워크스페이스 = 디지털 오피스
