## 2. 경쟁사별 최신 현황

### 2.1 노션 3.0 (2025.09.18 출시)

| 항목 | 내용 |
|------|------|
| **AI Agent** | 복잡한 다단계 작업 자동화 |
| **맥락 이해** | 노션 환경 + Slack, Google Drive + 웹 |
| **커스텀 에이전트** | ✅ 예정 (스케줄/트리거 기반 자율 실행) |

[노션 3.0의 강점]

> 📌 **시사점**: 노션이 커스텀 에이전트를 준비 중이므로, AI Note는 **캔버스 기반 맥락 이해**로 차별화해야 함

### 2.2 미로 (Miro)

| 항목 | 내용 |
|------|------|
| **Table/Kanban/Timeline** | ✅ 뷰 전환 지원 |
| **Jira/Trello 연동** | ✅ 양방향 동기화 |
| **Roadmap 기능** | ✅ 2024 출시 |
| **AI 기능** | 캔버스 내 보조 수준 |

```
[미로의 한계 - 검색 결과 확인됨]

1. 구조화 데이터 제한
   - 보드당 최대 250개 구조화 위젯 (Table, Timeline, Synced Cards)
   - 테이블당 최대 1,000행, 50열
   - 200행 초과 시 성능 저하

2. 캔버스 요소 ↔ 데이터베이스 통합 불가
   - 스티키 노트, 도형 등 일반 캔버스 요소는 테이블에 들어가지 않음
   - 테이블/칸반 내의 데이터를 찾아서 다른 곳에 넣기 어려움
   
3. 대형 보드 검색 성능 저하
   - 데이터가 많아지면 검색/로딩 느려짐
```

> 📌 **시사점**: 미로의 핵심 약점 = **"캔버스 요소가 데이터베이스에 들어가지 않는다"**

| **플러그인** | Canvas MindMap, Folder Canvas 등 |

[옵시디언 Canvas의 한계 - 검색 결과 확인됨]

### 2.5 ⚠️ AFFiNE (신규 강력 경쟁자)

| 항목 | 내용 |
|------|------|
| **문서 + 화이트보드 + DB** | ✅ 통합 |
| **Multi-View Mode** | ✅ 같은 콘텐츠를 문서/화이트보드/DB로 전환 |
| **AI 기능** | 요약, 번역, 마인드맵 생성, 프루프리딩 |
| **Make it Real** | ✅ 스케치 → 웹페이지 변환 |
| **Local-First** | ✅ 로컬 저장 + 클라우드 동기화 |

```
[AFFiNE의 강점]
- AI Note와 가장 유사한 비전
- 문서/화이트보드/DB의 진정한 통합
- Multi-View로 같은 데이터를 다른 형태로 보기

[AFFiNE의 한계 (추정)]
- 커스텀 에이전트/워크플로우 자동화 없음
- AI가 캔버스를 "직접 조작"하는지 불명확
- 4가지 맥락 같은 체계적 컨텍스트 엔지니어링 없음
```

> 📌 **시사점**: AFFiNE은 **직접적인 경쟁자**. 차별화 포인트를 명확히 해야 함.

## 4. AI Note의 진정한 차별화 포인트

### 4.1 ❌ 차별화가 약해진 것들

이제는 경쟁사도 하고 있어서 **단독 차별화가 아닌 것**:

| 기능 | 경쟁사 현황 |
|------|-------------|
| AI 문서 생성 | 노션 3.0, AFFiNE 모두 지원 |
| Multi-View (테이블/칸반) | AFFiNE 지원, 미로 부분 지원 |
| 화이트보드 AI 분석 | 헵타베이스가 앞서 있음 |
| 커스텀 에이전트 | 노션 3.0 예정 |

### 4.2 ✅ AI Note만의 차별화

#### 1️⃣ "캔버스의 모든 요소 = 데이터베이스 레코드"

```
[미로]
캔버스 요소 ──X──→ 테이블/칸반
(스티키 노트, 도형 등은 데이터베이스에 들어가지 않음)

[옵시디언]
Canvas 파일 ──X──→ Dataview/Bases
(Canvas는 DB 워크플로우에서 완전히 분리)

[AI Note]
캔버스의 모든 블록 ──→ 데이터베이스 레코드
(도형, 마크다운, 링크 모두 DB에 편입/이동 가능)
```

**유스케이스**:
- 브레인스토밍한 스티키 노트들 → 바로 테이블로 정리
- 캔버스에서 그린 유저플로우 도형들 → 칸반 보드로 전환
- 흩어진 아이디어들 → 기존 데이터베이스에 검색해서 편입

#### 2️⃣ "캔버스 전체를 이해하는 4가지 맥락"

```
[노션 3.0]
맥락 = 문서/DB + 연결된 외부 서비스 (Slack, Drive)
→ 캔버스/공간 개념 없음

[헵타베이스]
맥락 = 현재 화이트보드 구조 분석
→ 과거 작업 이력, 시맨틱 연결은 약함

[AI Note]
맥락 = 초점 + 의미 + 작업 + 액션
├─ 초점 맥락: 선택된 블록 + 엣지 연결 + 거리적으로 가까운 블록
├─ 의미 맥락: 발화와 시맨틱 서치로 연결된 블록 (벡터 임베딩)
├─ 작업 맥락: 과거 작업 이력
└─ 액션 맥락: 수행 가능한 블록 액션
```

**차별점**: 
- 공간적 근접성(거리)을 맥락으로 활용
- 시맨틱 서치로 의미적으로 가까운 블록 탐색
- 작업 이력 기반 장기 맥락

#### 3️⃣ "AI가 캔버스를 직접 조작"

```
[대부분의 경쟁사]
User: "이 내용을 정리해줘"
AI: "정리하면 이렇습니다: ..." (텍스트 답변)

[AI Note]
User: "이 내용을 정리해줘"
AI: [블록 생성] [엣지 연결] [위치 배치] (캔버스 직접 조작)
```

**구체적 기능**:
- AI가 마크다운 블록을 **직접 생성**
- Mermaid → 캔버스 블록으로 **자동 변환**
- AI가 블록 간 **엣지 연결**
- AI가 블록을 **데이터베이스에 편입**

#### 4️⃣ "시맨틱 서치 기반 캔버스 탐색"

```
[미로]
대형 보드에서 검색 성능 저하
텍스트 기반 검색만

[AI Note]
벡터 임베딩 기반 시맨틱 서치
"비슷한 의미"의 블록을 찾아줌
```

**유스케이스**:
- "저번에 만든 채용공고 관련 블록 어디 있지?" → 의미 기반 검색
- "이 아이디어와 관련된 다른 메모들 보여줘" → 유사 블록 탐색

#### 5️⃣ "캔버스 기반 커스텀 에이전트"

```
[노션 3.0 커스텀 에이전트]
- 문서/DB 기반
- 스케줄/트리거로 실행
- 시각화 없음

[AI Note 커스텀 에이전트]
- 캔버스 워크플로우 기반
- 인풋/아웃풋 블록 정의
- 워크플로우가 시각적으로 보임
- 중간 결과도 블록으로 추적 가능
```

**유스케이스** (자기소개서 도메인):
```
[커스텀 에이전트: 채용공고 분석기]
인풋: 링크 블록 (채용공고 URL)
    ↓
프로세스: 웹 크롤링 → 핵심 요구사항 추출
    ↓
아웃풋: 마크다운 블록 (분석 결과)
    + 자동으로 "채용공고" 데이터베이스에 편입
```

## 5. 차별화된 유스케이스

### 5.1 "브레인스토밍 → 정형화" 플로우

```
[기존 도구의 문제]
미로에서 브레인스토밍 → 노션으로 옮겨서 정리 → 수동 핸드오프

[AI Note]
1. 캔버스에서 자유롭게 브레인스토밍 (도형, 스티커, 마크다운)
2. AI: "이 아이디어들을 테이블로 정리해줘"
3. AI가 블록들을 데이터베이스에 편입 → 테이블 뷰로 전환
4. 핸드오프 없이 같은 공간에서 완료
```

### 5.2 "흩어진 데이터 → 기존 DB에 편입"

```
[기존 도구의 문제]
미로: 새 테이블 만들어야 함, 기존 테이블과 연결 어려움
옵시디언: 캔버스 요소를 DB에 넣을 수 없음

[AI Note]
1. 캔버스에 여러 링크 블록 추가 (채용공고들)
2. "이 공고들을 '채용공고' 데이터베이스에 추가해줘"
3. AI가 기존 DB를 찾아서 블록들을 편입
4. 테이블 뷰에서 기존 공고 + 새 공고 함께 관리
```

### 5.3 "맥락을 이해하는 AI 대화"

```
[기존 도구의 문제]
ChatGPT: 캔버스 맥락 없음
노션 AI: 현재 문서만 봄
미로 AI: 선택 영역만 봄

[AI Note]
User: "이 기획과 관련된 다른 아이디어들 찾아줘"
AI: [초점 맥락] 현재 선택된 블록과 엣지로 연결된 블록 확인
    [의미 맥락] 시맨틱 서치로 관련 블록 탐색
    [작업 맥락] 최근 작업한 블록 중 관련된 것 확인
→ 캔버스 전체에서 관련 블록들을 찾아서 보여줌
```

### 5.4 "워크플로우 추적 가능한 AI 작업"

```
[기존 도구의 문제]
AI가 한번에 결과만 출력 → 중간 과정 불투명

[AI Note]
1. AI가 작업하면서 중간 결과를 블록으로 생성
2. 각 단계가 캔버스에 시각적으로 표현
3. 잘못된 부분만 선택해서 다시 요청 가능
4. 워크플로우 전체를 추적/감사 가능
```

## 6. 결론: AI Note의 포지셔닝

### One-liner

> **AI Note** — 캔버스의 모든 것이 데이터가 되고, AI가 직접 조작하는 지식 워크스페이스

### vs 경쟁사

| 경쟁사 | AI Note의 차별점 |
|--------|-----------------|
| **노션 3.0** | 캔버스/시각화 + 공간적 맥락 이해 |
| **미로** | 모든 캔버스 요소의 DB화 + 시맨틱 검색 |
