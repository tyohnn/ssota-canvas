# Annual Roadmap 작성 가이드

이 가이드는 주니어 PM이 **Annual Roadmap**을 작성하는 전체 과정을 단계별로 안내합니다.

## 🎯 Annual Roadmap이란?

**Annual Roadmap**은 연간 계획 문서로, 분기별 Initiative와 성과를 관리합니다.

### 특징
- **범위**: 연간 계획 및 분기별 Initiative
- **기간**: 1년 (분기별 리뷰)
- **목적**: Project Vision을 실행 가능한 계획으로 변환
- **담당자**: PM, PO (경영진 승인)

---

## 📋 Step 0: 현재 날짜 확인

### 0.1 작업 시작 전 날짜 확인
```bash
# 현재 날짜 확인
date

# 예시 출력: Sun Sep 28 15:56:33 KST 2025
```

**날짜 확인 목적:**
- 현재 시점 파악으로 적절한 연간 계획 수립
- 분기별 Initiative 계획 시 정확한 타임라인 설정
- Project Vision과의 일치성 확인

## 📋 Step 1: Project Vision 검토

### 1.1 Project Vision 분석
```
❓ 질문: "Project Vision에서 올해 달성해야 할 목표는 무엇인가?"
```

**Project Vision 검토 체크리스트:**
- [ ] 현재 연도의 전략적 목표 파악
- [ ] 분기별 목표 상세 분석
- [ ] 성공 지표 및 KPI 확인
- [ ] 기술 전략과의 연결성 검토

### 1.2 현재 상황 분석
```
❓ 질문: "현재 프로젝트 진행 상황과 Vision의 차이는?"
```

**현황 분석 과정:**
1. **완료된 목표**: 이미 달성한 목표들 식별
2. **진행 중인 목표**: 현재 진행 중인 목표들 파악
3. **계획 중인 목표**: 앞으로 계획해야 할 목표들 정리
4. **갭 분석**: Vision과 현실 간의 차이 분석

## 📋 Step 2: 연간 목표 설정

### 2.1 연간 테마 정의
```
❓ 질문: "올해의 핵심 테마는 무엇인가?"
```

**연간 테마 작성 규칙:**
- **명확성**: 한 문장으로 표현 가능한 명확한 테마
- **집중성**: 올해 집중해야 할 핵심 영역
- **차별성**: 작년과 차별화되는 고유한 테마
- **달성 가능성**: 1년 내 달성 가능한 현실적 테마

**연간 테마 템플릿:**
```
"[핵심 영역]을 통해 [달성 목표]를 실현"
```

**예시:**
```
"고급 기능 및 AI 통합으로 차별화된 시장 경쟁력 확보"
```

### 2.2 연간 목표 검증
**검증 체크리스트:**
- [ ] Project Vision과 일치하는가?
- [ ] 현재 역량으로 달성 가능한가?
- [ ] 시장 상황을 반영하고 있는가?
- [ ] 팀의 동기를 부여할 수 있는가?

## 📋 Step 3: 분기별 Initiative 계획

### 3.1 분기별 Initiative 도출

**Initiative 도출 과정:**
1. **연간 목표 분해**: 연간 목표를 분기별로 분해
2. **우선순위 설정**: 분기별 우선순위 결정
3. **의존성 분석**: Initiative 간 의존성 파악
4. **리소스 할당**: 분기별 리소스 할당 계획

### 3.2 Epic 정의 수준 (중요)

**Annual Roadmap에서 Epic은 희미하고 느낌적인 수준으로만 정의합니다:**

**❌ 하지 말아야 할 것:**
- 구체적인 Command-Event 정의
- 세부적인 기능 명세
- Story 수준의 상세 분해

**✅ 해야 할 것:**
- 대략적인 기능 방향성 제시
- "이런 것들을 만들 예정" 수준의 개념적 정의
- Event Storming 전에 방향성만 잡는 수준

**예시:**
```
Epic 004: 컴포넌트 블록 시스템
- 사용자가 블록을 컴포넌트화하여 재사용할 수 있는 기능
- 피그마의 컴포넌트-인스턴스 개념과 유사한 구조
```

**구체화는 Event Storming 이후에:**
- Annual Roadmap → 희미한 Epic 목록
- Event Storming → 구체적인 도메인 분석
- Epic Planning → 실행 가능한 Epic 정의

**분기별 Initiative 템플릿:**
```markdown
### Q[분기] [연도]: [Initiative 이름] ([상태]) [아이콘]
**목표**: [분기별 핵심 목표]
- **Initiative [번호]**: [Initiative 이름]
  - Epic [번호]: [Epic 이름] - [희미하고 느낌적인 기능 소개]
  - Epic [번호]: [Epic 이름] - [희미하고 느낌적인 기능 소개]
  - Epic [번호]: [Epic 이름] - [희미하고 느낌적인 기능 소개]
  - Epic [번호]: [Epic 이름] - [희미하고 느낌적인 기능 소개]

**성공 지표**:
- [지표 1]: [목표값] [상태 아이콘]
- [지표 2]: [목표값] [상태 아이콘]
- [지표 3]: [목표값] [상태 아이콘]
```

### 3.3 Initiative 상태 관리

**상태 아이콘 가이드:**
- ✅ 완료 (Complete)
- 🔄 진행 중 (In Progress)
- 📋 계획 중 (Planned)

**상태 업데이트 규칙:**
- **분기 시작**: 📋 → 🔄
- **분기 완료**: 🔄 → ✅
- **지연 발생**: 상태 유지 + 설명 추가

## 📋 Step 4: 분기별 마일스톤 설정

### 4.1 마일스톤 정의

**마일스톤 설정 기준:**
- **측정 가능**: 완료 여부를 명확히 판단 가능
- **가치 지향**: 사용자나 비즈니스에 가치 제공
- **시간 제한**: 분기 말까지 완료 가능
- **검증 가능**: 객관적으로 검증 가능

**마일스톤 템플릿:**
```markdown
### Q[분기] 마일스톤 ([월]월 말)
- [ ] [마일스톤 1]: [구체적 완료 조건]
- [ ] [마일스톤 2]: [구체적 완료 조건]
- [ ] [마일스톤 3]: [구체적 완료 조건]
- [ ] [마일스톤 4]: [구체적 완료 조건]
```

### 4.2 마일스톤 검증
**검증 체크리스트:**
- [ ] Initiative 목표와 연결되는가?
- [ ] 분기 내 달성 가능한가?
- [ ] 측정 가능한 결과인가?
- [ ] 팀이 이해하기 쉬운가?


## 📋 Step 8: 이해관계자 승인

### 8.1 승인 대상자
- **PM**: 전체 로드맵 계획 승인
- **PO**: 제품 전략과의 일치성 승인
- **시니어 개발자**: 기술적 실현 가능성 승인
- **경영진**: 비즈니스 목표 및 리소스 승인

### 8.2 승인 프로세스
1. **초안 검토**: 이해관계자들에게 초안 공유
2. **피드백 수집**: 각 관점에서의 의견 수렴
3. **수정 및 보완**: 피드백 반영하여 문서 개선
4. **최종 승인**: 모든 이해관계자의 승인 확보

### 8.3 승인 체크리스트
- [ ] PM이 전체 로드맵 계획을 승인
- [ ] PO가 제품 전략과의 일치성을 승인
- [ ] 시니어 개발자가 기술적 실현 가능성을 승인
- [ ] 경영진이 비즈니스 목표를 승인

## 🔧 Git 워크플로우

### 브랜치 생성 및 작업
```bash
# 1. dev 브랜치에서 최신 상태로 업데이트
git checkout dev
git pull origin dev

# 2. Annual Roadmap 브랜치 생성
git checkout -b docs/annual-roadmap-2025

# 3. Annual Roadmap 작업
# - 연간 목표 설정
# - 분기별 Initiative 계획
# - 마일스톤 및 성공 지표 설정
# - 리뷰 프로세스 정의
```

### 커밋 메시지 규칙
```bash
# Annual Roadmap 문서 작성
git add .
git commit -m "docs(annual-roadmap): add 2025 annual roadmap document

- Set annual goal and theme for 2025
- Define quarterly initiatives and epics
- Establish milestones and success metrics
- Create quarterly review and adjustment process"

# 분기별 Initiative 추가
git add .
git commit -m "docs(annual-roadmap): add quarterly initiatives and milestones

- Q1: AI Integration Initiative (completed)
- Q2: Collaboration Initiative (completed)
- Q3: Advanced Animation Initiative (in progress)
- Q4: Enterprise Features Initiative (planned)"

# 성공 지표 및 리뷰 프로세스 추가
git add .
git commit -m "docs(annual-roadmap): add success metrics and review process

- Technical metrics: stability, performance, security
- User metrics: beta users, satisfaction, retention
- Business metrics: market readiness, competitiveness
- Quarterly review and adjustment process"
```

### GitHub에 푸시 및 PR 생성
```bash
# 1. 브랜치를 GitHub에 푸시
git push origin docs/annual-roadmap-2025

# 2. GitHub에서 Pull Request 생성
# - 제목: "Annual Roadmap 2025"
# - 설명: 2025년 연간 로드맵 및 분기별 Initiative 계획
# - 리뷰어: PM, PO, 시니어 개발자, 경영진
# - 라벨: annual-roadmap, planning, strategy
```

### PR 리뷰 체크리스트
**리뷰어가 확인할 사항:**
- [ ] **목표 명확성**: 연간 목표가 명확하고 달성 가능한가?
- [ ] **Initiative 적절성**: 분기별 Initiative가 목표 달성에 기여하는가?
- [ ] **마일스톤 현실성**: 마일스톤이 측정 가능하고 현실적인가?
- [ ] **지표 적절성**: 성공 지표가 구체적이고 의미있는가?
- [ ] **프로세스 체계성**: 리뷰 및 조정 프로세스가 체계적인가?

**승인 기준:**
- [ ] PM이 전체 로드맵 계획을 승인
- [ ] PO가 제품 전략과의 일치성을 승인
- [ ] 시니어 개발자가 기술적 실현 가능성을 승인
- [ ] 경영진이 비즈니스 목표를 승인
