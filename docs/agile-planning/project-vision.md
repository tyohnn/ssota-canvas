## 🎯 프로젝트 비전

**"AI와 인간이 하나의 웹 기반 플랫폼에서 소통하며, 모든 도메인과 워크플로우를 통합 관리할 수 있는 새로운 컴퓨팅 방식"**

## 💡 핵심 아이디어

### 해결하고자 하는 문제

- **워크플로우 분산**: 현재 기획(노션) → 계획(리니어/지라) → 디자인(피그마) → 개발(코딩도구)로 분산된 비효율성
- **AI-인간 소통 단절**: AI와 인간이 소통할 수 있는 통합된 SSOT(Single Source of Truth)의 부재
- **도메인별 분화**: 각 버티컬 도메인마다 별도 소프트웨어가 필요한 현실
- **핸드오프 비용**: 소프트웨어 단절로 인한 작업 전달 과정에서 발생하는 비효율 (전체 작업 시간의 약 30%)

### 핵심 솔루션

- **블록 기반 추상화**: 노션+피그마 방식의 블록 단위 확장 (마크다운, 도형, 이미지, 비디오, GitHub 연동, 코드, LaTeX 등)
- **화이트보드 기반**: 2차원 공간에서의 자유로운 사고와 정형화 과정
- **AI 통합**: 정형적 데이터 활용으로 AI가 쉽게 읽고 작업할 수 있는 구조
- **멀티 도메인**: 서비스 개발, 홈페이지 제작, 영상 제작, 이미지 편집, 3D 렌더링, 교육 등 지원
- **워크플로우 자동화**: AI 에이전트를 직접 정의하여 워크플로우 자동화

### 첫 번째 타겟 시장

- **지식 노동자 (One Knowledge Worker)** - AI를 레버리지 삼아 리서치, 기획, 문서 작업을 혼자서도 빠르게 해내고 싶은 지식 노동자
  - 바이브 코더 (비개발자 + AI로 개발)
  - 1인 기획자/창업자
  - 리서치가 많은 직군 (컨설턴트, 마케터, PM)
  - 취준생 (자기소개서, 면접 준비)
- **전략적 근거**: 작게 시작하여 빠르게 고객을 만나고 피드백을 수집하는 GTM 전략
- **Zero-to-One 접근**: 마크다운 + 도형 + 링크 3가지 블록으로 시작하여 하나의 유스케이스부터 시장 공략

## 📊 전략적 목표 (3년)

### 2025년: Foundation & Core Platform (진행 중) 🔄

**목표**: 블록 기반 추상화 시스템 완성 및 지식 노동자 시장 진입

- **Q1**: 프로젝트 기획 및 기술 스택 결정 ✅ (완료)
- **Q2**: 도메인 설계 및 아키텍처 수립 ✅ (완료)
- **Q3**: 핵심 플랫폼 기반 구축 ✅ (완료)
  - 사용자 관리, 조직 관리, 워크스페이스 구조 도메인 완료
  - 캔버스 기반 화이트보드 엔진 완료
  - 블록 시스템 기반 완료
- **Q4**: AI 통합 및 MVP 출시 🔄 (진행 중)
  - AI 에이전트 컨텍스트 엔지니어링 완료
  - MVP 글로벌 런칭 (2025.12 목표)
  - 지식 노동자 얼리어답터 확보

#### 개발 단계별 진행 상황

**1단계: 2차원 캔버스 위에 소프트웨어 일원화 표준화 작업** ✅ (완료)
- 다양한 데이터 타입을 블록으로 추상화
- 속성과 엣지를 통한 블록 간 관계 정의
- 블록 액션을 통한 데이터 상호변환 및 조작

**2단계: 캔버스와 블록 조작 UX/UI 구성** ✅ (완료)
- 2차원 캔버스 위 블록 자유 배치
- 에디터 패널을 통한 커스텀 속성 정의
- 엣지 연결을 통한 다양한 의미 관계 설정

**3단계: AI 에이전트 컨텍스트 엔지니어링** 🔄 (진행 중)
- 초점 맥락: 현재 선택된 블록 및 연결된 블록 (완료)
- 의미 맥락: 유저 발화와 의미적으로 가까운 블록 (진행 중)
- 작업 맥락: 캔버스 내 시기상 가까운 이벤트 (진행 중)
- 액션 맥락: 유저 발화 달성을 위한 블록 액션 정보 (완료)

**4단계: 커스텀 AI 에이전트 시스템** 📋 (계획 중)
- 유저가 직접 AI 에이전트 설계 가능
- 블록 관계 기반 워크플로우 정의
- 커스텀 프롬프트, 인풋/아웃풋 블록 양식 설정

## 🎯 핵심 차별화 포인트

### vs 기존 화이트보드/캔버스 서비스 (피그마, 미로 등)

- **블록 기반 추상화**: 피그마와 달리 다양한 블록 유형 지원 (코드, GitHub, LaTeX 등)
- **정형적 데이터 활용**: AI가 읽기 쉬운 구조화된 데이터로 자동화 가능
- **워크플로우 통합**: 디자인뿐만 아니라 제작 전체 과정 포함
- **노션의 정형성 + 미로의 시각화 + ChatGPT의 커스텀 에이전트**

### vs 노션 등 블록 기반 서비스

- **화이트보드 UI**: 2차원 공간에서의 자유로운 사고와 배치
- **다양한 보기 모드**: 화이트보드, 테이블, 칸반 등으로 변환 가능
- **AI 에이전트 통합**: 블록별 특화된 AI 툴 제공 (유튜브 요약, 이미지 생성 등)

### vs 개발 협업 도구 (리니어, 지라 등)

- **시각적 워크플로우**: 복잡한 개발 과정을 시각적으로 관리
- **AI 자동화**: 워크플로우를 AI 에이전트로 자동화 가능
- **통합 환경**: 기획부터 구현까지 한 곳에서 완료

## 🏗️ 기술 전략

### 핵심 기술 스택

- **Frontend**: Next.js (Server Actions), React Flow (화이트보드), TypeScript
- **Backend**: Next.js 풀스택 (Server Actions), Drizzle ORM
- **Database**: Supabase (PostgreSQL 기반)
- **Authentication**: Clerk (조직/계정 관리)
- **AI/ML**: OpenAI API, 블록별 특화 AI 모델
- **Infrastructure**: Vercel, Supabase Infrastructure

### 블록 시스템 우선순위

1. **MVP 블록**: 마크다운, 도형, 링크 블록 (현재 완료)
2. **기획 관련 블록**: 이미지, 오디오, 비디오 블록
3. **개발 관련 블록**: 코드 블록, GitHub 연동 블록
4. **협업 기능**: 실시간 편집, 댓글, 버전 관리 (블록이 아닌 플랫폼 기능)

### 아키텍처 원칙

- **모노레포**: 마이크로서비스 대신 통합된 코드베이스로 빠른 개발
- **동기 처리**: Event-driven이지만 이벤트 버스 없이 동기적 처리로 단순화
- **컴포넌트 중심**: iframe 기반 컴포넌트화로 디자인-개발 통합
- **AI-First**: 모든 블록과 워크플로우에 AI 통합을 기본으로 설계
