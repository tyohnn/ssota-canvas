## 🎯 Software Design Overview

Process Model에서 식별된 System을 Aggregate로 전환하고, Inbox Management의 Bounded Context를 정의합니다. Inbox는 **단일 Bounded Context**이며, 세션·메시지 생명주기와 Source Job 결과 반영을 하나의 **Inbox Session Aggregate**로 담당합니다. 페이지 추천은 **Domain Service**(Page Recommendation Handler)가 AI Management와 연동한 뒤 이벤트 발행 및 Read Model 갱신만 수행합니다.

### 🟪 External System 처리
- **Source Domain - Job System**: 콜백 페이로드 → 도메인 명령(RecordSourceJobCompleted / RecordSourceJobFailed) 변환용 **ACL** 적용
- **Block Management - Block System**: Block 생성 요청/응답을 도메인 모델로 변환하는 **ACL**
- **Workspace Management - Page System**: 페이지 목록·권한 조회 — API 응답을 도메인/Read Model에 맞게 변환하는 **ACL**
- **Canvas Management - Block Mount System**: 마운트 요청을 해당 도메인 API에 맞게 변환하는 **ACL**
- **AI Management - Recommendation System**: 추천 요청/응답 변환 **ACL**
- **Storage (Supabase)**: 업로드 URL·메타데이터 변환 **ACL**

## 📦 Aggregate 상세 정의

### 1. Inbox Session Aggregate

**핵심 개념**: 워크스페이스 단위의 Quick Capture Inbox 세션. 한 세션에 여러 메시지(Inbox Message)가 속하며, 각 메시지는 소스 타입·Block 참조·Source Job 처리 상태를 가진다.

**Root Entity**: InboxSession (식별자: InboxSessionId)

#### Commands (Process Model 매핑)
- **CreateInboxSession**: 현재 워크스페이스에 활성 세션이 없을 때 새 세션 생성 (Inbox 진입 요청 → 권한 검증 후)
- **RestoreInboxSession**: 기존 활성 세션이 있을 때 해당 세션 복원
- **AddInboxMessage**: 세션에 메시지 추가 (소스 타입, 소스 데이터 참조; Block 생성·Source Job 등록은 Application/Service 레이어에서 ACL 통해 수행 후 blockId·jobId 전달)
- **RecordSourceJobCompleted**: Source Job 완료 콜백 수신 시 해당 메시지 상태를 요약완료로 갱신 (이벤트 미발행, Read Model 갱신)
- **RecordSourceJobFailed**: Source Job 실패 콜백 수신 시 해당 메시지를 실패 상태로 갱신하고 **Inbox Message Processing Failed** 발행

#### Events (Process Model 매핑)
- **Inbox Session Created**: 세션 생성 또는 복원 완료 시 1회 발행
- **Inbox Message Added**: 메시지 추가 및 Block·Source Job 연결 완료 후 1회 발행
- **Inbox Message Processing Failed**: Source Job 실패 시 1회 발행

#### 핵심 불변식 (Invariants)
- Inbox 세션과 메시지는 반드시 하나의 워크스페이스에 속한다 (워크스페이스 격리).
- 동일 워크스페이스 내에서는 활성 세션이 하나만 존재한다 (복원 시 기존 세션 재사용).
- 메시지 추가 시 Block 생성 및 Source Job 등록이 완료된 후에만 **Inbox Message Added**를 발행한다.
- Source Job 완료 시 도메인 이벤트는 발행하지 않고, 실패 시에만 **Inbox Message Processing Failed**를 발행한다.
- Inbox 메시지 삭제 기능은 제공하지 않는다 (사용자 삭제 불가).

#### 포함 엔티티
- **InboxMessage**: 세션에 속한 단일 메시지. 소스 타입, 소스 참조, blockId, jobId(선택), 처리 상태(업로드됨 / 추출중 / 요약완료 / 실패) 보유.

#### 속성 (Root 및 엔티티 요약)
```typescript
// Root
interface InboxSession {
  sessionId: InboxSessionId;
  workspaceId: WorkspaceId;
  status: 'active';
  createdAt: IsoDateTime;
  messages: InboxMessage[];
}

interface InboxMessage {
  messageId: InboxMessageId;
  sourceType: 'file' | 'link' | 'audio' | 'memo' | 'youtube' | string;
  sourceRef: string;           // Storage URL, URL, 텍스트 참조 등
  blockId: BlockId;            // Block Management에서 생성 후 연결
  jobId?: SourceJobId;         // Source Domain Job 등록 후
  processingStatus: 'uploaded' | 'extracting' | 'summary_complete' | 'failed';
}
```

## 🔲 Bounded Context 정의

### Inbox Management Context (Core Domain)

**언어적 특징**:
- **Inbox Session** = 워크스페이스 단위 Quick Capture 진입 시 생성/복원되는 단위
- **Inbox Message** = 세션에 추가된 단일 캡처(파일/링크/오디오/메모 등), Block과 1:1 연결, Source Job으로 추출/요약
- **Processing Status** = 업로드됨 → 추출중 → 요약완료 또는 실패

**핵심 책임**:
- Inbox 세션 생성·복원 및 워크스페이스 격리
- 메시지 추가 시 Block·Source Job 연동 (Service 레이어 + ACL)
- Source Job 완료/실패 콜백 수신 시 메시지 상태 반영
- 페이지 추천 결과 수신 시 이벤트 발행 및 Read Model 갱신 (Domain Service)

**포함된 Aggregates / Services**:
- **Inbox Session Aggregate** (세션·메시지 일관성 경계)
- **Page Recommendation Handler** (Domain Service: AI 연동, 이벤트 발행, Read Model 갱신)

**External System Integration**:
- **Source Domain - Job System**: Job 등록 API, 완료/실패 Webhook 또는 폴링 — ACL로 페이로드 → 도메인 명령 변환
- **Block Management - Block System**: Block 생성 동기 API — ACL
- **Workspace Management - Page System**: 페이지 목록·권한 조회 — ACL
- **Canvas Management - Block Mount System**: Block 마운트 동기 API — ACL
- **AI Management - Recommendation System**: 추천 API 호출 — ACL
- **Storage (Supabase)**: 업로드 URL 획득 — ACL

## 🔀 다른 Context와의 경계

### Source Domain과의 경계
- **언어적 차이**: Inbox는 "메시지 처리 상태", Source는 "Job·추출 결과" SSOT.
- **통합**: Inbox가 Job 등록 후 콜백 수신 → ACL이 Job 완료/실패 페이로드를 RecordSourceJobCompleted / RecordSourceJobFailed로 변환.

### Block Management와의 경계
- **언어적 차이**: Inbox는 "메시지에 연결된 Block", Block Management는 Block 생성·타입 검증 SSOT.
- **통합**: 메시지 추가 시 Block 생성 API 호출(ACL) → blockId를 메시지에 연결 후 **Inbox Message Added** 발행.

### Workspace Management와의 경계
- **언어적 차이**: Inbox는 "워크스페이스 격리", Workspace는 페이지·권한 SSOT.
- **통합**: 세션 생성/복원 전 권한 검증, 페이지 목록 조회(추천 시) — ACL로 응답 변환.

### Canvas Management와의 경계
- **언어적 차이**: Inbox는 "추천 후 사용자 선택", Canvas는 Block 마운트 위치 SSOT.
- **통합**: 사용자 페이지 선택 시 Block Mount API 호출(ACL); Inbox는 추천만 제공하고 마운트는 Canvas 쪽에서 수행.

### AI Management와의 경계
- **언어적 차이**: Inbox는 "페이지 추천 후보 n개", AI는 추천 결과 생성 SSOT.
- **통합**: Page Recommendation Handler가 AI API 호출(ACL) → **Page Recommendations Generated by LLM** 발행 및 Read Model 갱신.

## 💡 핵심 설계 결정

### 1. 단일 Aggregate: Inbox Session + Messages
- **문제**: 세션과 메시지의 일관성 경계(트랜잭션, 불변식)를 어떻게 잡을지.
- **해결**: Inbox Session을 Root로 하고 Inbox Message를 포함 엔티티로 두어, 세션 단위로 일관성 유지.
- **대안**: Session Aggregate와 Message Aggregate 분리 — 메시지 추가 시 Saga/이벤트로 연동. 이 경우 트랜잭션 경계와 실패 보상이 복잡해짐.
- **결정 이유**: Process Model상 "세션에 속한 메시지 목록"이 강하게 묶여 있고, 메시지 삭제가 없어 단일 트랜잭션 경계로 충분함.

### 2. 요약 완료 시 이벤트 미발행
- **문제**: Source Job 완료 시 도메인 이벤트를 발행할지 여부.
- **해결**: Process Model대로 "별도 이벤트 없이 Read Model 갱신"만 수행.
- **결정 이유**: 완료는 이미 콜백으로 들어오며, 구독자가 제한적이라 Read Model 갱신만으로 충분; 실패만 명시적 이벤트로 처리.

### 3. 페이지 추천을 Aggregate가 아닌 Domain Service로 처리
- **문제**: Page Recommendations Generated by LLM을 누가 발행하고 추천 데이터를 어디에 둘지.
- **해결**: Page Recommendation Handler(Domain Service)가 AI Management ACL을 통해 호출 후, 이벤트 발행 및 Read Model(PageRecommendationsView) 갱신.
- **결정 이유**: 추천은 세션/메시지의 불변식이 아니며, LLM 결과만 반영하면 되므로 별도 Aggregate 없이 서비스로 처리.

## 📖 Read Models (Query Side)

### InboxSessionView
**목적**: /inbox 진입 시 세션 존재 여부, 세션 ID, 해당 세션의 메시지 목록 제공.

```typescript
interface InboxSessionView {
  sessionId: InboxSessionId;
  workspaceId: WorkspaceId;
  exists: boolean;
  messages: InboxMessageItem[];
}

interface InboxMessageItem {
  messageId: InboxMessageId;
  sourceType: string;
  blockId: BlockId;
  processingStatus: 'uploaded' | 'extracting' | 'summary_complete' | 'failed';
  summary?: string;  // 요약 완료 시
}
```

**최적화**: 세션·메시지 목록은 워크스페이스·세션 단위로 캐싱(예: 5분 TTL); 메시지 추가/상태 변경 시 무효화. Realtime 또는 폴링으로 3~10초 내 요약 상태 반영 목표.

---

### InboxMessageStatusView
**목적**: 메시지별 처리 상태(업로드됨 / 추출중 / 요약완료 / 실패) 표시.

```typescript
interface InboxMessageStatusView {
  messageId: InboxMessageId;
  processingStatus: 'uploaded' | 'extracting' | 'summary_complete' | 'failed';
  failedReason?: string;  // 실패 시 로그/모니터링용, 선택적 노출
}
```

**최적화**: InboxSessionView의 messages 내 상태와 동기화; 실패 시 상태 표시 영역에 반영.

---

### PageRecommendationsView
**목적**: 메시지(Block)별 LLM 페이지 추천 후보 n개(제목, 추천 이유, 확신도), 추천 미생성/실패 시 재시도 옵션.

```typescript
interface PageRecommendationsView {
  messageId: InboxMessageId;
  blockId: BlockId;
  status: 'pending' | 'ready' | 'failed';
  recommendations?: Array<{
    pageId: PageId;
    title: string;
    reason: string;
    confidence: number;
  }>;
  retryAvailable?: boolean;
}
```

**최적화**: 요약 완료와 추천 호출을 파이프라인으로 처리해 지연 최소화; 사용자 Page 목록 캐싱으로 LLM 입력 준비 시간 단축.

## 🤝 Service 레이어의 역할

- **업무 시나리오 연결**: Inbox 진입 시 권한 검증(Workspace) → Create/Restore 세션. 메시지 추가 시 Block 생성(Block Management) → blockId 연결 → Source Job 등록(Source Domain) → AddInboxMessage 및 **Inbox Message Added** 발행. 추천 요청 시 Page 목록 조회(Workspace) → AI 호출(AI Management) → **Page Recommendations Generated by LLM** 발행 및 Read Model 갱신.
- **규칙 준수 확인**: 워크스페이스 격리, 활성 세션 1개, idempotency key(Source Job 콜백) 적용.
- **외부 파트너 연동**: Source Job Webhook/폴링, Block/Canvas/Workspace/AI/Storage 각 ACL을 통해 호출·응답 변환 및 에러를 도메인 예외로 변환.
- **실패 대응**: Job 실패 시 **Inbox Message Processing Failed** 발행 및 상태 표시; 추천 실패 시 재시도 또는 수동 선택 옵션 제공. 재시도는 Message Queue 시스템에서 자동 처리.
- **사용자 경험**: 업로드 즉시 Block 생성으로 카드 표시(낙관적 UI), 상태는 비동기 갱신.

## 🛡️ Anti-Corruption Layer Design

### Source Domain - Job System ACL
- **목적**: Job 완료/실패 콜백 페이로드를 도메인 명령(RecordSourceJobCompleted, RecordSourceJobFailed)으로 변환. 외부 Job 스키마 변경으로부터 Inbox 도메인 보호.
- **위치**: `src/domains/inbox/infrastructure/SourceJobResultAdapter.ts` (가칭)
- **변환 규칙**:
  - 콜백 payload.jobId → SourceJobId, payload.status → 완료/실패 구분
  - payload.messageId 또는 inbox_message 매핑 → InboxMessageId
  - 워크스페이스 격리·idempotency key 검증 후 Aggregate 명령 호출
- **에러 처리**: 콜백 검증 실패 시 로그 및 재시도 정책(Message Queue); 도메인 검증 실패 시 도메인 예외로 변환.

### Block Management - Block System ACL
- **목적**: Block 생성 요청(소스 타입·참조)을 Block Management API 형식으로 변환하고, 응답(blockId)을 도메인 BlockId로 변환.
- **위치**: `src/domains/inbox/infrastructure/BlockManagementAdapter.ts` (가칭)
- **변환 규칙**: 도메인 CreateBlockRequest → API 스펙; API 응답.id → BlockId
- **에러 처리**: 타임아웃·재시도 정책 정의; API 에러를 도메인 예외로 변환.

### Workspace Management - Page System ACL
- **목적**: 페이지 목록·권한 조회 API 응답을 도메인/Read Model용 구조로 변환.
- **위치**: `src/domains/inbox/infrastructure/WorkspacePageAdapter.ts` (가칭)
- **변환 규칙**: API 페이지 목록 → PageId, title 등 도메인/뷰 필드
- **에러 처리**: RLS/권한 실패 시 도메인 예외 또는 빈 목록 반환.

### Canvas Management - Block Mount System ACL
- **목적**: 사용자 페이지 선택 시 Block 마운트 요청을 Canvas API 형식으로 변환.
- **위치**: `src/domains/inbox/infrastructure/BlockMountAdapter.ts` (가칭)
- **변환 규칙**: blockId, pageId, 위치 정보 → API 스펙
- **에러 처리**: 타임아웃·재시도; API 에러를 도메인 예외로 변환.

### AI Management - Recommendation System ACL
- **목적**: LLM 추천 요청/응답을 도메인 모델(메시지·페이지 목록·추천 n개)로 변환.
- **위치**: `src/domains/inbox/infrastructure/AIRecommendationAdapter.ts` (가칭)
- **변환 규칙**: AI 응답 스키마 → PageRecommendationsView.recommendations 형식; 권한(페이지 목록)과 일치 검증
- **에러 처리**: 추천 실패 시 재시도 또는 수동 선택 옵션(Read Model에 반영).

### Storage (Supabase) ACL
- **목적**: 업로드 URL·메타데이터를 도메인 sourceRef 및 Block/Source Job 전달 형식으로 변환.
- **위치**: `src/domains/inbox/infrastructure/StorageAdapter.ts` (가칭)
- **변환 규칙**: Storage URL → sourceRef; 메타(크기, 타입) 검증 후 Block·Job에 전달
- **에러 처리**: 업로드 실패 시 도메인 예외로 변환.

## 📊 성과 측정 지표

1. **Inbox 세션·메시지 처리**: 세션 생성/복원 및 메시지 추가 요청이 정상 처리되는 비율
2. **Source Job 반영 지연**: Job 완료 후 3~10초 내 요약 상태가 Read Model에 반영되는 비율
3. **추천 성능**: 요약 완료부터 추천 결과 표시까지 파이프라인 지연 시간
4. **실패 대응**: Inbox Message Processing Failed 발생 시 사용자에게 상태가 정확히 표시되는지
