## 📊 Domain Overview

**비즈니스 가치**:
사용자가 메시지 보내듯이 업무 맥락(링크, 파일, 오디오, 메모)을 빠르게 인입하고, 시스템이 자동으로 추출·요약·분류하여 블록으로 저장하고, AI가 적합한 페이지를 추천하여 "넣는 순간 정리된다"는 체감 와우를 제공하는 입력 허브.

**다른 도메인과의 관계**:
- **Source Domain**: 추출/요약 처리 — **Source Job**에 등록하여 Source 도메인 시스템 활용
- **Block Management Domain**: 소스 → 블록 생성, 블록 타입 검증
- **Workspace Management Domain**: 페이지 목록 조회, 권한 검증
- **Canvas Management Domain**: 블록 마운트 (Block Mount to Page)
- **AI Management Domain**: LLM 기반 요약, 페이지 추천 생성

## 📝 핵심 개념 정리

### Inbox 핵심 구조
```
Inbox Flow
├── Inbox Session (세션/스레드)
│   ├── Inbox Message (인입된 소스 단위)
│   │   ├── Source Type (파일/오디오/메모/링크/유튜브)
│   │   ├── Block (생성된 유니크 소스)
│   │   └── Processing Status (업로드됨/추출중/요약완료/실패)
│   └── 같은 세션 = 약한 맥락 공유 (페이지 추천 정확도 향상)
├── Source Processing (비동기)
│   ├── Extract (텍스트/메타데이터 추출)
│   ├── Summarize (요약 생성)
│   └── Classify (소스 타입 분류, 태깅)
└── Page Recommendation
    ├── LLM 입력: Block 요약 + 사용자 Page 목록 + (선택) 세션 맥락
    ├── LLM 출력: 추천 Page 후보 n개
    └── 사용자 선택 → Block Mount to Page
```

### Domain Scope/Boundary
- **Inbox Session**: 인입 흐름 단위, 같은 세션의 입력은 맥락 공유
- **Inbox Message**: 소스 인입 단위 (채팅 버블에 해당)
- **Source**: 파일/링크/오디오/메모/유튜브 등 원본 데이터
- **Block (from Inbox)**: 소스로부터 생성된 유니크 블록
- **Block Mount**: Block을 Page(캔버스)에 배치하는 연결

### Business Rules/Policies
- **즉시 Block 생성**: 업로드 즉시 Block 생성하여 성공감 제공, 추출/요약은 비동기
- **처리 상태 표시**: 업로드됨 → 추출중 → 요약완료 (또는 실패)
- **페이지 추천 + 사용자 선택**: 자동 마운트 없음, 추천 배지 클릭 시에만 마운트
- **같은 세션 = 약한 힌트**: 페이지 추천 시 가중치만 반영, 자동 확정 X
- **워크스페이스 격리**: Inbox 세션/메시지는 워크스페이스 단위로 격리

## 🟠 Domain Events (시간 순서)

Inbox Management **도메인 내부**에서만 발생하는 이벤트.  
(프론트엔드·다른 도메인·호출 요청 이벤트 제외, Source 도메인 이벤트는 별도 정의)

### 1. Inbox 세션 및 메시지 (Inbox Session & Message)

- Inbox 세션이 생성되었다 (Inbox Session Created)
  - *사용자가 /inbox 진입 시 새 세션 또는 기존 세션 복원*
- Inbox 세션에 메시지가 추가되었다 (Inbox Message Added)
  - *소스 인입 시 메시지 추가. 이후 Inbox는 Block 생성 요청 및 **Source Job 등록**으로 Source 도메인 시스템 활용 (추출/요약 비동기 처리)*
- Inbox 메시지가 삭제되었다 (Inbox Message Deleted)
  - *사용자가 인입 취소 시 (선택 기능)*

### 2. 페이지 추천 결과 (Page Recommendation Result)

- LLM이 페이지 추천을 생성했다 (Page Recommendations Generated by LLM)
  - *Inbox가 AI를 호출한 결과를 수신한 사실. 추천 Page 후보 n개, 추천 이유, 확신도*

### 3. 처리 실패 및 재시도 (Processing Failure & Retry)

- Inbox 메시지 처리가 실패했다 (Inbox Message Processing Failed)
  - *특정 메시지에 대한 처리(추출/요약 등) 실패. 다른 도메인과 동일한 "[작업] Failed" 패턴*
  - *대응 Command: Process Inbox Message (또는 Source 도메인 처리 트리거)*
- Inbox 메시지 처리 재시도가 시작되었다 (Inbox Message Processing Retry Initiated)
  - *재시도 요청(Command)이 수락되어 실제 재시도가 시작된 사실*
  - *대응 Command: Inbox Processing Retry Requested*

## 🔵 Commands & Actors

### 주요 시나리오 (Command → Event 1:1 대응)

#### Scenario 1: Inbox 세션 생성 및 메시지 추가
- **시스템이 Inbox 세션 생성/복원하기** (System) → Inbox Session Created
- **시스템이 Inbox 메시지 추가하기** (System) → Inbox Message Added  
  - *사용자 소스 인입 시. 오케스트레이션: Block 생성 요청 → **Source Job 등록**(Source 도메인) → 추출/요약 비동기 수행*

#### Scenario 2: 페이지 추천 결과 수신
- **Inbox가 AI 서비스 호출 후 결과 수신** (System) → Page Recommendations Generated by LLM

#### Scenario 3: 처리 실패 및 재시도
- **메시지 처리 시도** (System / Source 도메인) → 성공 시 (Source 도메인 이벤트) / 실패 시 **Inbox Message Processing Failed**
- **사용자 또는 시스템이 Inbox 처리 재시도 요청하기** (User / System) → **Inbox Processing Retry Requested** (Command)
- **시스템이 재시도 수락 후 처리 시작** (System) → **Inbox Message Processing Retry Initiated** (Event)

#### Scenario 4: 메시지 삭제
- **사용자가 Inbox 메시지 삭제하기** (User) → Inbox Message Deleted

### 식별된 액터 분류

#### Primary Actors (직접 사용자)
- **Inbox User**: 소스 인입, 페이지 추천 선택, 카드 상세 조회 담당

#### System Actors (내부 시스템)
- **Extraction Service**: 소스에서 텍스트/메타데이터 추출 (PDF, 오디오 전사 등)
- **Summarization Service**: LLM 기반 요약 생성
- **Page Recommendation Service**: LLM 기반 페이지 추천 생성
- **Inbox Session Manager**: 세션 생성/복원, 메시지 연결

#### External Domains (외부 도메인)
- **Source Domain**: **Source Job 등록** — 추출/요약 비동기 처리에 Source 도메인 Job 시스템 활용
- **Block Management Domain**: 소스 → 블록 생성, 블록 타입 검증
- **Workspace Management Domain**: 페이지 목록 조회, 권한 검증
- **Canvas Management Domain**: 블록 마운트 처리
- **AI Management Domain**: LLM 호출 (요약, 페이지 추천)
- **Storage (Supabase)**: 파일/오디오 업로드 저장

## 🟠 Bounded Context 정의

### Inbox Management Context (Main Context)

**책임**:
- Quick Capture 입력 허브 관리 (세션, 메시지)
- Block/Source/Canvas/Workspace/AI 도메인 호출 오케스트레이션 (호출 자체는 이벤트로 정의하지 않음)

**핵심 언어**:
Inbox, Inbox Session, Inbox Message, Page Recommendations Generated, Inbox Message Processing Failed, Inbox Message Processing Retry Initiated

**핵심 용어 및 개념**:
- **Inbox**: 소스 수집/정리/라우팅을 위한 입력 허브 (`/inbox`)
- **Inbox Session**: 인입 흐름 단위, 같은 세션의 입력은 약한 맥락 공유
- **Inbox Message**: 소스 인입 단위, Block과 1:1 연결
- **Page Recommendations Generated**: AI 호출 결과로 추천 목록을 수신한 사실
- **Inbox Message Processing Failed**: 특정 메시지 처리 실패 (다른 도메인과 동일한 "[작업] Failed" 패턴)
- **Inbox Message Processing Retry Initiated**: 재시도 요청(Command)에 따른 재시도 시작 사실

**포함 이벤트** (도메인 내부만):
- Inbox 세션 및 메시지 (3개): Inbox Session Created, Inbox Message Added, Inbox Message Deleted
- 페이지 추천 결과 (1개): Page Recommendations Generated by LLM
- 처리 실패 및 재시도 (2개): Inbox Message Processing Failed, Inbox Message Processing Retry Initiated

**총 6개 이벤트**

## 🔗 Context 간 관계 및 통합점

(다른 도메인 호출은 이벤트로 정의하지 않음. Process Model에서 호출 시점·파라미터만 정의.)

### Inbox Management ↔ Block Management Domain
- **연결점**: Inbox Message 추가 시 블록 생성 요청
- **통합 방식**: 동기적 서비스 호출 (블록 생성 후 Inbox Message에 block_id 연결)

### Inbox Management ↔ Source Domain
- **연결점**: Inbox Message 추가 후 **Source Job에 등록** — Source 도메인의 Job 시스템을 활용해 추출/요약 비동기 처리
- **통합 방식**:
  - Inbox는 메시지(또는 Block) 단위로 **Source Job 등록** API/서비스를 호출
  - Source 도메인이 Job 큐에서 추출·요약 수행 (검증/추출/요약은 Source 도메인 이벤트)
  - Job 실패·타임아웃 시 Inbox에서는 **Inbox Message Processing Failed** 기록; 재시도 시 동일하게 Source Job 재등록
- **의존성**: Inbox는 Source 도메인 시스템(Job 등록·조회)을 활용하므로 Process Model에서 Source Job 스키마·API 정합 필요

### Inbox Management ↔ Canvas Management Domain
- **연결점**: 사용자 페이지 선택 시 블록 마운트 요청
- **통합 방식**: 동기적 서비스 호출 (Canvas API 호출)

### Inbox Management ↔ Workspace Management Domain
- **연결점**: 페이지 목록 조회, 권한 검증
- **통합 방식**: RLS, 페이지 목록 API 조회

### Inbox Management ↔ AI Management Domain
- **연결점**: LLM 호출 (페이지 추천). 결과 수신 시 **Page Recommendations Generated by LLM**
- **통합 방식**: AI Service 호출 (동기 또는 비동기)

## 🔴 Hotspots (문제점/병목)

### 우선순위: 높음

1. **추출/요약 비동기 처리 및 실패 복구**
   - 문제: 추출/요약이 오래 걸리거나 실패 시 사용자 경험 저하
   - 영향: "넣는 순간 정리된다" 체감 약화
   - 해결: 즉시 Block 생성 + 처리 상태 실시간 표시, 실패 시 재시도 UI, 3~10초 내 첫 요약 표시 목표

2. **LLM 페이지 추천 지연**
   - 문제: 요약 완료 후 LLM 호출로 추천 생성 시 추가 지연
   - 영향: 추천 배지 표시까지 시간 증가
   - 해결: 요약과 추천을 파이프라인으로 연속 호출, 캐싱(사용자 Page 목록)

3. **소스 타입별 추출 파이프라인 차이**
   - 문제: PDF/오디오/유튜브/링크 등 타입별 추출 로직이 다름
   - 영향: 파이프라인 복잡도, 에러 핸들링 분기
   - 해결: Source Type별 추출기(Extractor) 플러그인 구조, 공통 인터페이스

### 우선순위: 중간

4. **Inbox 세션과 맥락 활용**
   - 문제: 같은 세션 입력을 "약한 힌트"로만 쓰면 활용도 제한
   - 영향: 페이지 추천 정확도 향상 여지
   - 해결: MVP에서는 세션 ID만 전달, Post-MVP에서 세션 내 이전 메시지 요약을 추가 컨텍스트로 활용

5. **모바일 입력 UX**
   - 문제: 모바일에서 파일/오디오 인입 시 네이티브 앱 대비 제약
   - 영향: Quick Capture 핵심 사용처(이동 중, 회의 중)에서 마찰
   - 해결: PWA + Share Target API, 모바일 웹 최적화

6. **대용량 파일 처리**
   - 문제: 대용량 PDF/오디오 업로드 시 처리 시간 증가
   - 영향: 체감 와우 저하
   - 해결: 파일 크기 제한, 청크 단위 추출, 진행률 표시

### 우선순위: 낮음

7. **Inbox 메시지 정리/삭제**
   - 문제: 인입 취소, 잘못된 소스 제거 시 Block 처리
   - 영향: Block은 이미 생성됨, 마운트되지 않으면 "고아" 블록 가능
   - 해결: 마운트되지 않은 Block은 일정 기간 후 정리 배치, 또는 사용자 삭제 시 Soft Delete

8. **세션 장기 보관**
   - 문제: Inbox 세션을 얼마나 보관할지
   - 영향: 스토리지, 검색 성능
   - 해결: MVP에서는 세션 메타만 저장, 상세 이력은 Block/Message에 의존

## 💡 Opportunities (개선 기회)

### 즉시 구현 (MVP 필수)

1. **Quick Capture Inbox 핵심 플로우**
   - 기회: 소스 인입 → 블록 생성 → 추출 → 요약 → 카드 표시
   - 구현: /inbox 페이지, 소스 타입별 업로드 UI, 채팅형 버블, 처리 상태 표시

2. **페이지 추천 배지 + 마운트**
   - 기회: 추천 Page를 배지로 표시, 클릭 시 마운트
   - 구현: LLM 페이지 추천 API, 배지 UI, Block Mount 연동

3. **바텀시트 상세**
   - 기회: 카드 클릭 시 원문 메타, 추출 텍스트, 요약, 핵심 포인트 표시
   - 구현: 바텀시트 컴포넌트, Block 상세 데이터 조회

4. **처리 상태 실시간 반영**
   - 기회: 업로드됨 → 추출중 → 요약완료 전환을 실시간 표시
   - 구현: 폴링 또는 Realtime 구독, 낙관적 UI

5. **Inbox 세션 기본 구조**
   - 기회: 세션 단위로 메시지 그룹핑, 추후 맥락 활용
   - 구현: inbox_sessions, inbox_messages 테이블, 세션 생성/복원 로직

### 향후 구현 (Post-MVP)

6. **모바일 Share to SSOTA** *(메모)*
   - 유튜브/브라우저/파일앱에서 "SSOTA로 보내기"

7. **브라우저 확장 Send to SSOTA** *(메모)*
   - 현재 페이지 클릭 한 번으로 보내기

8. **세션 기반 맥락 강화** *(메모)*
   - 같은 세션 내 이전 메시지 요약을 페이지 추천 컨텍스트에 추가

9. **관련 기존 자료 추천** *(메모)*
   - 요약 기반 시맨틱 검색으로 관련 Block 추천

## ❓ Process Modeling을 위한 주요 질문들

### 1. 소스 인입 및 검증
- Q: 각 소스 타입별 허용 형식/크기 제한은?

## 🔗 연관 도메인

### Block Management Domain과의 관계
- **연결점**: Inbox Message 추가 시 블록 생성 요청
- **통합 방식**: Block Management API 호출 (호출 자체는 Inbox 이벤트 아님)

### Source Domain과의 관계
- **연결점**: Inbox Message 추가 후 **Source Job 등록** — Source 도메인 Job 시스템에 작업을 넣어 추출/요약 수행
- **통합 방식**: Inbox가 Source 도메인의 Job 등록 API를 호출하여 해당 도메인 시스템 활용; Job 실패 시 Inbox Message Processing Failed, 재시도 시 Source Job 재등록
- **참고**: Source 도메인 Event Storm에서 Job 등록·실행·완료/실패 이벤트 정의 필요

### Canvas Management Domain과의 관계
- **연결점**: 사용자 페이지 선택 시 블록 마운트 요청
- **통합 방식**: Canvas Management API 호출

### Workspace Management Domain과의 관계
- **연결점**: 페이지 목록, 권한
- **통합 방식**: 페이지 조회 API, RLS

### AI Management Domain과의 관계
- **연결점**: LLM 페이지 추천 호출; 결과 수신 시 Page Recommendations Generated by LLM
- **통합 방식**: AI Service 호출
