## 📍 Scenario 1: 조직 접근 및 Workspace-Page 목록 조회 및 페이지 선택

### 비즈니스 컨텍스트

- **Process Model 참조**: Scenario 1 in `02-process-model.md`
- **사용자 목표**: 
  - 조직 페이지에 접근하여 모든 Workspace의 Page 목록을 확인
  - 작업할 페이지를 선택하여 열기
  - 최근 방문한 페이지로 자동 이동
  
- **주요 제약**: 
  - 조직 멤버만 접근 가능
  - Workspace 멤버십에 따라 페이지 접근 제한
  - Default Workspace는 조직 멤버 모두 접근 가능
  - 일반 Workspace는 초대받은 멤버만 접근 가능

### Screen 1: 조직 Workspace 레이아웃 (로딩 상태)

**화면 구성**:
```
┌─────────────────────────────────────────────────────────────┐
│ [조직 선택 ▼]                                               │
├──────────────────┬──────────────────────────────────────────┤
│                  │                                          │
│  [스켈레톤 라인] │    [페이지 제목 스켈레톤]                │
│  [스켈레톤 라인] │                                          │
│  [스켈레톤 라인] │    [캔버스 콘텐츠 스켈레톤 블록들]        │
│  [스켈레톤 라인] │                                          │
│  [스켈레톤 라인] │                                          │
│                  │                                          │
└──────────────────┴──────────────────────────────────────────┘
  ↑ 사이드바 (280px)   ↑ 메인 영역
```

**UI 컴포넌트**:

**헤더 영역**:
- **조직 선택 드롭다운** (`OrganizationSwitcher`):
  - 현재 선택된 조직명 표시
  - 드롭다운 아이콘 (ChevronDown)
  - Organization Domain 컴포넌트 재사용

**사이드바 영역 (로딩 중)**:
- **너비**: 280px (데스크톱)
- **스켈레톤 UI**:
  - 스켈레톤 라인 5-7개
  - shimmer 애니메이션 효과
  - 높이: 각 라인 24px
  - 간격: 8px
  - 배경: gray-200
  
**메인 영역 (로딩 중)**:
- **페이지 헤더 스켈레톤**:
  - 제목 라인 (너비: 200px, 높이: 32px)
  - 부제 라인 (너비: 120px, 높이: 16px)
  
- **캔버스 스켈레톤**:
  - 블록 스켈레톤 3-5개
  - 각 블록: 높이 40-80px (랜덤)
  - 여백: 좌우 96px (데스크톱)

**인터랙션**:
- 인터랙션 없음 (로딩 중)

**화면 전환**:
- **조건**: 데이터 로드 완료
- **전환**: Screen 1 → Screen 2
- **전환 방식**: 스켈레톤에서 실제 콘텐츠로 fade-in

**애니메이션**:
- 스켈레톤 shimmer 효과: 좌→우 방향, 1.5s 반복
- 전환 애니메이션: fade-in 150ms ease-in-out

### Screen 2: 조직 Workspace 레이아웃 (로드 완료)

**화면 구성**:
```

│ SSOTA | 📁 Acme Corp / Welcome                              │ ← Breadcrumb
├──────────────────┬──────────────────────────────────────────┤

│   📄 회의록      │                                          │

│                  │                                          │

**UI 컴포넌트**:

**사이드바 영역** (메인 콘텐츠):

1. **즐겨찾기 섹션** (최상단):
   - **헤더**:
     - 아이콘: ⭐ (별)
     - 텍스트: "즐겨찾기" (font-semibold, text-sm)
     - 색상: text-gray-700
   
   - **즐겨찾기 페이지 목록** (플랫 리스트):
     - 각 페이지 아이템:
       - 페이지 아이콘 (16x16px)
       - 페이지 제목 (truncate)
       - 패딩: 8px 12px
       - 간격: 2px
     - 즐겨찾기 없는 경우:
       - 회색 텍스트: "즐겨찾기한 페이지가 없습니다"
       - 폰트 크기: text-xs
   
   - **구분선** (Separator):
     - 높이: 1px
     - 색상: border-gray-200
     - 여백: 상하 8px

2. **Workspaces 섹션** (즐겨찾기 하단):
   - **섹션 헤더**:
     - 아이콘: 📁 (폴더)
     - 텍스트: "Workspaces" (font-semibold, text-sm)
     - 색상: text-gray-700
     - **+ 버튼** (우측):
       - 아이콘: Plus (lucide-react)
       - 크기: 16x16px
       - 색상: text-gray-500
       - 호버: text-gray-900, 배경 gray-100 (rounded)
       - 클릭: Workspace 생성 모달 열기 (Scenario 2)
       - **권한**: 조직 소유자만 표시
   
   - **구분선** (헤더 하단):
     - 높이: 1px
     - 색상: border-gray-200
     - 여백: 상하 8px
   
   **A. Default Workspace** (최상단, "기본" 배지):
   - **헤더**:
     - 아이콘: 조직 아이콘 또는 기본 📁
     - 이름: 조직명 (예: "Acme Corp")
     - "기본" 배지: 작은 회색 배지 (text-xs, bg-gray-100)
     - Chevron 아이콘: › / ∨ (접기/펼치기, 왼쪽)
     - **삼점 메뉴** (우측 끝):
       - 아이콘: MoreHorizontal (..., lucide-react)
       - 크기: 16x16px
       - 색상: text-gray-400
       - 호버: text-gray-900, 배경 gray-100 (rounded)
       - 클릭: 컨텍스트 메뉴 표시
   
   - **컨텍스트 메뉴**:
     - "워크스페이스 설정" (Scenario 2 Sequence 2)
     - "멤버 추가" (Scenario 3) - **조직 Admin + Workspace 멤버만**
     - "워크스페이스 보관" (Scenario 8) - **비활성화** (Default는 삭제 불가)
   
   - **페이지 트리**:
     - 접힌 상태: Chevron › (오른쪽 향함)
     - 펼쳐진 상태: Chevron ∨ (아래 향함)
     - 하위 페이지 목록 표시 (접기/펼치기 가능)
   
   **B. 일반 Workspace들**:
   - **헤더**:
     - 아이콘: Workspace별 커스텀 아이콘 (이모지 또는 이미지)
     - 이름: Workspace 이름 (예: "마케팅 팀")
     - Chevron 아이콘: › / ∨ (왼쪽)
     - **삼점 메뉴** (우측 끝):
       - 동일한 스타일
       - 클릭: 컨텍스트 메뉴 표시
   
   - **컨텍스트 메뉴**:
     - "워크스페이스 설정" (Scenario 2 Sequence 2)
     - "멤버 추가" (Scenario 3) - **조직 Admin + Workspace 멤버만**
     - "워크스페이스 보관" (Scenario 8) - **조직 소유자만**
   
   - **페이지 트리**: Default Workspace와 동일 구조

3. **페이지 아이템** (각 Workspace 내부):
   - **구조**:
     - 페이지 아이콘 (16x16px): 커스텀 아이콘 (기본: 📄)
     - 페이지 제목: truncate 처리
     - Chevron (하위 페이지 있는 경우): › / ∨
   
   - **들여쓰기** (계층 구조):
     - 최상위 페이지: 들여쓰기 없음
     - 1단계 하위: 16px 들여쓰기
     - 2단계 하위: 32px 들여쓰기
     - 3단계 이상: 48px 들여쓰기 (최대)
   
   - **상태 표시**:
     - 기본 상태: 배경 투명
     - 호버 상태: 배경 gray-50
     - 선택 상태: 배경 primary-50, 왼쪽 보더 (primary-500, 2px)
   
   - **하위 페이지 펼치기/접기**:
     - 부모 페이지 앞에 Chevron 표시
     - 클릭 시 하위 페이지 토글
     - 상태는 로컬 스토리지에 저장 (persistence)

4. **빈 Workspace 표시**:
   - 페이지가 0개인 경우:
     - 회색 텍스트: "페이지를 생성하세요"
     - 폰트 크기: text-xs
     - 색상: text-gray-500
     - 패딩: 8px 12px

**메인 영역**:

**Workspace 헤더** (Breadcrumb):
- **SSOTA 브랜딩**:
  - 텍스트: "SSOTA"
  - 위치: 좌측 상단
  
- **구분선 (Separator)**:
  - 수직 구분선
  - 높이: 16px

- **Breadcrumb 경로**:
  - **Workspace 항목**:
    - Workspace 아이콘 (16x16px)
    - Workspace 이름
    - 클릭: Workspace 첫 페이지로 이동
  
  - **구분선**: "/" (BreadcrumbSeparator)
  
  - **Page 항목** (선택된 페이지):
    - Page 제목
    - truncate 처리
    - 클릭 불가 (현재 페이지)

**페이지 헤더** (인라인 편집 영역):
- **좌측 영역** (flex, items-center, gap-3):
  - **페이지 아이콘**:
    - 크기: 32x32px
    - 클릭 가능 (편집용, Scenario 4에서 다룸)
    - 호버 시 배경 강조 (편집 힌트)
  
  - **페이지 제목**:
    - 폰트: text-2xl, font-bold
    - 클릭 가능 (편집용, Scenario 4에서 다룸)
    - 호버 시 배경 강조 (편집 힌트)
  
  - **메타 정보**:
    - 마지막 수정 시간 (text-xs, text-gray-500)
    - 예: "2분 전 수정됨"

- **우측 영역**:
  - **즐겨찾기 Star 아이콘** (Scenario 5)
    - 위치: 우측 상단
    - 크기: 20x20px
    - 상태: 채워진 ⭐ / 빈 ☆

**페이지 캔버스**:
- **여백**: 
  - 좌우: 96px (데스크톱)
  - 상단: 24px
  - 하단: 48px
  
- **콘텐츠**:
  - 블록 시스템 영역 (Block System Domain, 미래)
  - 현재는 빈 상태 또는 "Welcome" 기본 텍스트

**인터랙션**:

1. **페이지 아이템 클릭**:
   - **동작**:
     - 선택 상태 변경 (배경색 primary-50)
     - 이전 선택 해제
     - URL 변경: `/r/[orgId]/workspace/[workspaceId]/page/[pageId]`
     - 메인 영역에 페이지 콘텐츠 로드 (Screen 3으로 전환)
     - 쿠키에 pageId 저장 (key: `recent-page-${orgId}`, value: `<pageId>`)
     - Workspace 멤버십 검증 요청 (Server Component)
   
   - **로딩**:
     - 선택 상태는 즉시 변경 (낙관적 업데이트)
     - 메인 영역만 로딩 상태로 전환
     - 사이드바는 그대로 유지

2. **Workspace 헤더 Chevron 클릭**:
   - **동작**:
     - Chevron 방향 전환: › ↔ ∨
     - 하위 페이지 목록 토글 (펼치기/접기)
     - 로컬 스토리지에 상태 저장 (key: `workspace-collapsed-${workspaceId}`)
   
   - **애니메이션**:
     - 슬라이드 다운/업 (200ms ease-out)
     - 높이 자동 계산

3. **부모 페이지 Chevron 클릭**:
   - **동작**:
     - Chevron 방향 전환: › ↔ ∨
     - 하위 페이지 토글 (펼치기/접기)
     - 로컬 스토리지에 상태 저장 (key: `page-collapsed-${pageId}`)
   
   - **애니메이션**: Workspace와 동일

4. **페이지 아이템 호버**:
   - 배경색 변경: transparent → gray-50
   - 커서: pointer
   - 전환 시간: 100ms ease-in-out

5. **즐겨찾기 페이지 클릭**:
   - 페이지 아이템 클릭과 동일한 동작
   - 해당 Workspace의 페이지로 이동
   - Workspace 섹션도 자동으로 펼쳐짐

**권한별 UI 차이** (Software Design 기준):
- **조직 멤버 (공통)**:
  - 모든 Workspace 목록 표시 (초대 여부 무관)
  - Default Workspace의 모든 페이지 접근 가능 (자동 허용)
  - 일반 Workspace는 멤버십 확인 필요
  
- **Workspace 멤버**:
  - 초대받은 Workspace의 페이지 접근 가능
  - 초대받지 않은 Workspace의 페이지 클릭 시 → Screen 4 (권한 없음 페이지)
  
- **Workspace 비멤버**:
  - Workspace 목록에는 표시됨 (조직 멤버이므로 가시성 있음)
  - 페이지 클릭 시 Workspace 멤버십 검증 실패
  - 검증 실패 시 → Screen 4 (권한 없음 페이지)
  
- **조직 비멤버**:
  - 페이지 진입 자체가 차단됨 (Server Component에서 403 Forbidden)
  - Workspace-Page 목록 로드 전에 즉시 차단 (Fail-fast)

**화면 전환**:
- **조건 1**: 권한 있는 페이지 선택
  - **전환**: Screen 2 유지 (메인 영역만 업데이트)
  - **전환 방식**: 메인 영역 fade-out → Screen 3 (로딩) → fade-in

- **조건 2**: 권한 없는 페이지 선택
  - **전환**: Screen 2 → Screen 4 (권한 없음 페이지)
  - **전환 방식**: 메인 영역만 fade-out → fade-in

**애니메이션**:
- **페이지 전환**: 
  - 메인 영역 fade-out/in (150ms ease-in-out)
  - 사이드바는 애니메이션 없음
  
- **Workspace/페이지 펼치기/접기**: 
  - 슬라이드 다운/업 (200ms ease-out)
  - 높이 자동 계산 (max-height transition)
  
- **선택 상태 변경**: 
  - 즉시 적용 (애니메이션 없음)
  - 배경색만 transition (100ms)

**접근성**:
- **키보드 내비게이션**:
  - Tab: 페이지 아이템 간 이동
  - Enter/Space: 페이지 선택
  - Arrow Up/Down: 페이지 목록 탐색
  - Arrow Left/Right: Workspace/페이지 접기/펼치기
  
- **스크린 리더**:
  - 각 페이지 아이템에 aria-label
  - 선택 상태: aria-selected="true"
  - 펼침/접힘 상태: aria-expanded="true/false"

### Screen 3: 페이지 선택 중 (로딩 상태)

**화면 구성**:

- **메인 영역**: 스켈레톤 UI로 전환

**UI 컴포넌트**:

**사이드바**:

  - 페이지 클릭 → 사이드바 자동 닫기
  - 메인 영역에 페이지 표시

  - 오른쪽 스와이프 (화면 왼쪽 가장자리에서) → 사이드바 열기
  - 왼쪽 스와이프 (사이드바에서) → 사이드바 닫기

**특이사항**:
- **사이드바 너비**: 전체 화면의 80% (최대 320px)
- **헤더 조정**:
  - 조직 선택 드롭다운: 조직명만 표시 (드롭다운 아이콘 축소)
- **페이지 제목**: text-xl → text-lg (폰트 크기 축소)
- **페이지 아이템**: 
  - 패딩 증가 (터치 영역: 최소 44px 높이)
  - 폰트 크기 유지 또는 약간 증가 (가독성)

**애니메이션** (모바일 전용):
- 사이드바 슬라이드 인/아웃: 300ms ease-out
- backdrop fade-in/out: 200ms ease-in-out

## 📍 Scenario 3: Admin이 Workspace에 멤버 초대 및 수락/거절

### 비즈니스 컨텍스트

- **Process Model 참조**: Scenario 3 in `02-process-model.md`
- **Software Design 참조**: Scenario 3 in `03-software-design.md`
  - Commands: InviteWorkspaceMember, AcceptWorkspaceInvitation, RejectWorkspaceInvitation
  - Events: WorkspaceMemberInvitationCreated, InvitationNotificationSent, WorkspaceInvitationAccepted, MemberAddedToWorkspace, WorkspaceInvitationRejected, NotificationUpdated
  - Server Actions: inviteWorkspaceMemberAction, acceptWorkspaceInvitationAction, rejectWorkspaceInvitationAction
  
- **사용자 목표**: 
  - Admin: 팀 멤버를 Workspace에 초대하여 협업 활성화
  - 멤버: 초대를 확인하고 수락 또는 거절
  
- **주요 제약**: 
  - 조직 Admin이면서 Workspace 멤버만 초대 가능
  - 조직 멤버만 초대 가능 (외부 이메일 불가)
  - 이미 Workspace 멤버인 경우 초대 불가
  - 초대받은 본인만 수락/거절 가능
  - 알림과 초대는 동기 처리 (둘 다 성공해야 함)

**성공 시** (페이지 정보 수정):
- **UI 반응**: 
  - 제목/아이콘 즉시 변경
  - 사이드바 자동 업데이트
  - Toast 없음 (자연스러운 수정)
- **다음 액션**: 
  - 계속 작업 가능
  - 다시 편집 가능

**실패 시** (네트워크 오류, 서버 오류):
- **UI 반응**: 
  - Toast: "페이지 생성/이동/수정에 실패했습니다" (에러, 5초)
  - 낙관적 업데이트 롤백 (원래 상태로 복원)
- **다음 액션**: 
  - 재시도 가능

**권한 부족** (Workspace 비멤버):
- **UI 반응**: 
  - + 버튼 숨김
  - 드래그 불가
  - 제목/아이콘 클릭 불가
- **서버 에러 시**:
  - Toast: "권한이 없습니다" (에러, 3초)

**유효성 검증 실패** (제목 빈 문자열):
- **UI 반응**: 
  - Toast: "페이지 제목을 입력해주세요" (에러, 3초)
  - 편집 모드 유지
  - Input 자동 포커스
- **다음 액션**: 
  - 제목 재입력

**순환 참조** (페이지 이동):
- **UI 반응**: 
  - Toast: "페이지를 이동할 수 없습니다" (에러, 3초)
  - 원래 위치로 복원
- **다음 액션**: 
  - 다른 위치로 이동 시도

## 📍 Scenario 5: 멤버가 페이지를 즐겨찾기에 추가/제거

### 비즈니스 컨텍스트

- **Process Model 참조**: Scenario 5 in `02-process-model.md`
- **Software Design 참조**: Scenario 5 in `03-software-design.md`
  - Command: ToggleFavorite
  - Events: PageAddedToFavorites, PageRemovedFromFavorites
  - Server Action: togglePageFavoriteAction
  
- **사용자 목표**: 
  - 자주 사용하는 페이지를 즐겨찾기에 추가하여 빠른 접근
  - 즐겨찾기 페이지는 사이드바 최상단에 표시
  
- **주요 제약**: 
  - Workspace 멤버만 즐겨찾기 관리 가능
  - 즐겨찾기는 개인별로 관리 (다른 멤버와 공유 안 됨)
  - 즐겨찾기 추가 또는 제거 (토글)

---

### Screen 1: 즐겨찾기 토글

**트리거**: 
- 메인 영역 페이지 헤더에서 **별 아이콘** 클릭
- **권한**: Workspace 멤버만

**화면 구성**:
```
┌─────────────────────────────────────────────┐
│  SSOTA | 📁 마케팅 팀 / 캠페인 계획          │  ← Breadcrumb
├─────────────────────────────────────────────┤
│                                             │
│  📄 캠페인 계획                    ☆        │  ← 제목 + 즐겨찾기 아이콘
│  2분 전 수정됨                              │
│                                             │
│  [캔버스 콘텐츠]                             │
│                                             │
└─────────────────────────────────────────────┘
```

**UI 컴포넌트**:

**즐겨찾기 아이콘** (페이지 헤더 우측):
- **추가되지 않음**: ☆ (Star 아이콘, 비어있음)
- **추가됨**: ⭐ (Star 아이콘, 채워짐, 노란색)
- 아이콘 크기: 일반 (20x20px)
- 호버: 크기 약간 증가 (scale)
- 클릭: 즉시 토글 (낙관적 업데이트)

**사이드바 즐겨찾기 섹션**:
- 최상단에 즐겨찾기 페이지 목록 표시
- 플랫 리스트 (계층 구조 없음)
- 추가 시 자동으로 목록에 추가
- 제거 시 자동으로 목록에서 제거

**인터랙션**:

1. **별 아이콘 클릭**:
   - 즉시 아이콘 토글 (낙관적 업데이트)
   - ☆ → ⭐ (추가) 또는 ⭐ → ☆ (제거)
   - 사이드바 즐겨찾기 섹션 자동 업데이트
   - Screen 2 (처리 중) 전환

2. **호버**:
   - 아이콘 크기 약간 증가
   - Tooltip 표시:
     - "즐겨찾기에 추가" (비추가 상태)
     - "즐겨찾기에서 제거" (추가 상태)

**권한별 UI 차이**:
- **Workspace 멤버**: 별 아이콘 표시, 클릭 가능
- **Workspace 비멤버**: 별 아이콘 숨김

**화면 전환**:
- **조건**: 별 아이콘 클릭
- **전환**: 즉시 아이콘 및 사이드바 업데이트 (낙관적 업데이트)

---

### Screen 2: 즐겨찾기 처리 중 (백그라운드)

**화면 구성**:
- 별 아이콘 즉시 변경됨 (낙관적 업데이트)

**인터랙션**:

**화면 전환**:
- **조건 1**: 토글 성공 → 상태 유지
- **조건 2**: 토글 실패 → Toast 에러, 원래 상태로 복원

**UI 컴포넌트**:
- 별 아이콘: 최종 상태 표시
- 사이드바 즐겨찾기 섹션: 최종 목록 표시

**인터랙션**:
- 일반 인터랙션 가능
- 다시 클릭하여 재토글 가능

**화면 구성**:
```

   - 페이지 선택 상태 표시

   - Chevron 클릭 → 목록 토글
