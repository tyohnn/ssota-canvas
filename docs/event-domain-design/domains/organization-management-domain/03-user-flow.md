## 📍 Scenario 0: 조직 조회 및 선택

### 비즈니스 컨텍스트

- **Process Model 참조**: Scenario 0 in `02-process-model.md`
- **사용자 목표**: 유저 가입/로그인 후 작업할 조직 선택
- **주요 제약**: 
  - 자동 트리거 (사용자 입력 없음)
  - 초기 조직 자동 선택 (쿠키 > 기본 조직 > 첫 번째 소유 조직)
  - User Management Domain 연동

---

### Screen 1: 메인 대시보드 (조직 선택 UI)

**화면 구성**:
- **사이드바** (좌측):
  - 상단: 조직 선택 드롭다운 (`OrganizationSwitcher`)
  - 중단: 워크스페이스 메뉴 (Workspace Domain)
  - 하단: 인박스, 설정 버튼
- **메인 영역** (우측):
  - 워크스페이스 콘텐츠 영역

**UI 컴포넌트** (조직 선택 드롭다운):
- **OrganizationSwitcher** (`shadcn/ui` DropdownMenu):
  - **Trigger 버튼**:
    - 현재 선택된 조직 이름 표시
    - 기본 조직인 경우 "기본" 배지 표시
    - 드롭다운 아이콘 (ChevronDown)
  
  - **드롭다운 메뉴 콘텐츠**:
    - **조직 목록** (정렬 규칙 적용됨):
      - 소유 조직 우선 표시
      - 이후 참여일(joined_at) 오름차순
      - 각 조직 아이템:
        - 조직 이름
        - 기본 조직: "기본" 배지 (파란색)
        - 현재 선택: 체크 아이콘
    - **구분선** (Separator)
    - **"새 조직 만들기" 버튼**:
      - 아이콘: Plus
      - 텍스트: "새 조직 만들기"

**자동 프로세스** (사용자 인터랙션 없음):
- **초기 로드 시**:
  1. `getUserOrganizationsAction()` 자동 호출
  2. 조직 목록 조회 (소유 + 멤버 조직)
  3. 초기 조직 자동 선택:
     - 쿠키에 저장된 조직 ID 확인
     - 쿠키 없으면 기본 조직 선택
     - 기본 조직 없으면 첫 번째 소유 조직 선택
  4. 선택된 조직 ID를 쿠키에 저장
  5. OrganizationContext 상태 업데이트
  6. 선택된 조직이 드롭다운에 표시됨

**인터랙션** (사용자 수동 선택):
- 드롭다운 Trigger 클릭 → 메뉴 열림
- 조직 아이템 호버 → 배경색 변경 (hover:bg-accent)
- 조직 아이템 클릭 → 조직 선택
  - 선택된 조직으로 컨텍스트 전환
  - 쿠키에 조직 ID 저장
  - URL 이동: `/r/[orgId]/workspace`
  - 드롭다운 자동 닫힘
  - 워크스페이스 목록 새로고침 (Workspace Domain)
- "새 조직 만들기" 클릭 → 조직 생성 다이얼로그 열림 (Scenario 1)

**화면 전환**:
- **조건**: 조직 선택 시
- **전환**: URL 이동 `/r/[orgId]/workspace`
- **전환 방식**: 클라이언트 사이드 라우팅 (Next.js)

**상태 피드백**:
- 로딩 상태: 조직 목록 조회 중 스켈레톤 UI
- 선택 상태: 현재 조직 체크 아이콘 표시
- 에러 상태: Toast 메시지 ("조직 목록을 불러오지 못했습니다")

**접근성**:
- 키보드 네비게이션: Arrow Up/Down으로 조직 이동, Enter로 선택
- 스크린 리더: "조직 선택 메뉴", "[조직명] 선택됨"
- 포커스 관리: 드롭다운 열림 시 첫 번째 아이템에 포커스

## 📍 Scenario 1: 새로운 조직 생성

### 비즈니스 컨텍스트

- **Process Model 참조**: Scenario 1 in `02-process-model.md`
- **사용자 목표**: 새로운 프로젝트를 위한 별도 조직 생성
- **주요 제약**: 
  - 인증된 사용자만 생성 가능
  - 조직 이름 및 타입 필수 입력
  - 생성자가 자동으로 소유자가 됨

---

### Screen 1: 조직 생성 다이얼로그

**화면 구성**:
- **다이얼로그 헤더**:
  - 제목: "새 조직 만들기"
  - 닫기 버튼 (X 아이콘)
  
- **다이얼로그 본문**:
  - 조직명 입력 필드
  - 조직 타입 선택 드롭다운
  
- **다이얼로그 푸터**:
  - 취소 버튼
  - 생성 버튼

**UI 컴포넌트** (`CreateOrganizationDialog`):

**1) 조직명 입력 필드**:
- Label: "조직 이름" (필수 표시: *)
- Input: 텍스트 입력 필드
  - Placeholder: "우리 팀 이름을 입력하세요"
  - 최대 길이: 100자
  - 실시간 검증: Zod 스키마
- 에러 메시지: 
  - 빈 값: "조직 이름을 입력해주세요"
  - 중복: "이미 존재하는 조직 이름입니다"

**2) 조직 타입 선택 드롭다운**:
- Label: "조직 타입" (필수 표시: *)
- Select: 드롭다운 메뉴
  - 옵션:
    - "개인" (personal)
    - "교육" (education)
    - "스타트업" (startup)
    - "에이전시" (agency)
    - "컴퍼니" (company)
    - "해당 없음" (n/a)
- 기본값: "해당 없음"

**3) 액션 버튼**:
- **취소 버튼**:
  - 스타일: 기본 버튼 (테두리만)
  - 텍스트: "취소"
  - 클릭: 다이얼로그 닫기 (입력 내용 초기화)
  
- **생성 버튼**:
  - 스타일: 주요 버튼 (bg-primary)
  - 텍스트: "생성"
  - 로딩 상태: 스피너 + "생성 중..."
  - 비활성화 조건: 필수 필드 미입력 또는 로딩 중

**인터랙션**:
- **다이얼로그 열기**:
  - OrganizationSwitcher의 "새 조직 만들기" 클릭
  - 다이얼로그 페이드인 애니메이션
  
- **폼 입력**:
  - 조직명 입력 → 실시간 검증
  - 조직 타입 선택 → 드롭다운 메뉴
  
- **생성 버튼 클릭**:
  1. 폼 검증 (Zod)
  2. `createNewOrganizationAction()` 호출
  3. 로딩 상태: 버튼 비활성화 + 스피너
  4. 성공 시:
     - 다이얼로그 닫기
     - 조직 목록 자동 갱신
     - 새 조직으로 자동 선택
     - URL 이동: `/r/[newOrgId]/workspace`
     - Toast: "조직이 생성되었습니다"
  5. 실패 시:
     - 다이얼로그 열린 상태 유지
     - 에러 메시지 표시 (인라인 또는 Toast)
  
- **취소 버튼 클릭** 또는 **다이얼로그 외부 클릭** 또는 **ESC 키**:
  - 다이얼로그 닫기
  - 입력 내용 초기화

**화면 전환**:
- **조건**: 조직 생성 성공
- **전환**: 다이얼로그 닫힘 + 새 조직으로 자동 선택
- **전환 방식**: URL 자동 변경 `/r/[newOrgId]/workspace`

**애니메이션**:
- 다이얼로그 열기: 페이드인 + 스케일업 (duration: 200ms)
- 다이얼로그 닫기: 페이드아웃 + 스케일다운 (duration: 150ms)
- 로딩 스피너: 회전 애니메이션 (infinite)

**에러 처리**:
- **조직명 중복**: "이미 존재하는 조직 이름입니다" (인라인 에러)
- **네트워크 오류**: "조직 생성에 실패했습니다. 다시 시도해주세요" (Toast)
- **검증 오류**: 필드 아래 빨간색 에러 메시지 표시

**접근성**:
- 다이얼로그 열림 시 포커스: 조직명 입력 필드
- Tab 키: 입력 필드 → 타입 선택 → 취소 → 생성
- ESC 키: 다이얼로그 닫기
- 스크린 리더: "조직 생성 다이얼로그"

## 📍 Scenario 2: 멤버 초대 및 수락

### 비즈니스 컨텍스트

- **Process Model 참조**: Scenario 2 in `02-process-model.md`
- **사용자 목표**: 
  - (Sequence 1) 조직에 새 멤버 초대
  - (Sequence 2) 초대받은 조직에 참여
- **주요 제약**: 
  - 소유자와 관리자만 멤버 초대 가능
  - 이미 멤버이거나 초대 진행 중인 경우 선택 불가
  - Notification Management Domain 연동

---

### Screen 1: 설정 다이얼로그

**화면 구성**:
- **전체 화면 다이얼로그** (최대 너비 제한):
  - **좌측 사이드바** (250px):
    - 설정 카테고리 네비게이션
    - "기본", "멤버", "프로필" 메뉴
  - **우측 콘텐츠 영역**:
    - 선택된 카테고리의 설정 내용

**UI 컴포넌트** (`SettingsDialog`):

**좌측 사이드바**:
- **카테고리 네비게이션**:
  - "기본" 탭: 조직 기본 설정
  - "멤버" 탭: 멤버 초대 및 관리 ⭐
  - "프로필" 탭: 사용자 프로필 설정
  - 선택된 탭: 배경색 하이라이트

**인터랙션**:
- 사이드바 설정 버튼 클릭 → 설정 다이얼로그 열림
- "멤버" 탭 클릭 → 멤버 초대 화면 표시 (Screen 2)
- 다이얼로그 외부 클릭 또는 ESC 키 → 다이얼로그 닫기

**화면 전환**:
- **조건**: "멤버" 탭 선택
- **전환**: Screen 1 → Screen 2 (멤버 초대 탭)
- **전환 방식**: 탭 전환 (같은 다이얼로그 내)

**반응형**:
- **모바일** (768px 미만): 좌측 사이드바 숨김, 상단 탭으로 전환
- **태블릿/데스크톱**: 좌측 사이드바 + 우측 콘텐츠

---

### Screen 2: 멤버 초대 탭 (설정 다이얼로그 내)

**화면 구성**:
- **상단 섹션**: 현재 멤버 목록
  - 멤버 리스트 (프로필 이미지, 이름, 이메일, 역할, 가입일)
  - 진행 중인 초대 목록 (회색 표시)
  
- **하단 섹션**: 멤버 초대 폼
  - 이메일 입력 필드 (자동 검색)
  - 검색 결과 목록
  - 역할 선택 필드
  - 초대 버튼

**UI 컴포넌트** (`MemberInvitationForm`):

**1) 현재 멤버 목록** (`MemberList`):
- **멤버 아이템** (각 멤버별):
  - 프로필 이미지 (Avatar, 40x40)
  - 이름 (text-sm font-medium)
  - 이메일 (text-xs text-gray-600)
  - 역할 배지 (Badge):
    - "소유자": 보라색
    - "관리자": 파란색
    - "멤버": 회색
  - 가입일 (text-xs text-gray-500)
  - **역할 변경 버튼** (Scenario 3에서 표시)

- **진행 중인 초대** (회색 표시):
  - 이메일
  - "초대 중" 배지 (회색)
  - "취소" 버튼 (선택사항)

**2) 이메일 검색 입력**:
- Label: "멤버 초대"
- Input: 
  - Placeholder: "이메일 주소를 입력하세요"
  - 디바운싱: 300ms
  - 자동 검색: 입력 시 `searchUserByEmail()` 호출

**3) 검색 결과 Selector**:
- **검색 결과 아이템** (각 사용자별):
  - 프로필 이미지 (Avatar, 32x32)
  - 이름 (text-sm)
  - 이메일 (text-xs text-gray-600)
  - 상태 표시:
    - 이미 멤버: "이미 멤버입니다" (선택 불가, 회색)
    - 초대 진행 중: "초대 중" (선택 불가, 회색)
    - 초대 가능: 호버 효과 (선택 가능)

**4) 선택된 사용자 배지**:
- 프로필 이미지 (작은 아이콘)
- 이름
- 제거 버튼 (X 아이콘)

**5) 역할 선택 드롭다운**:
- Label: "부여할 역할"
- Select:
  - "관리자" (admin)
  - "멤버" (member)
- 기본값: "멤버"

**6) 초대 버튼**:
- 텍스트: "초대하기"
- 스타일: bg-primary
- 비활성화 조건: 사용자 미선택 또는 로딩 중

**권한별 UI 차이**:
- **소유자**:
  - 멤버 초대 폼 모두 표시
  - 모든 기능 사용 가능
  
- **어드민**:
  - 멤버 초대 폼 모두 표시
  - 모든 기능 사용 가능
  
- **일반 멤버**:
  - 멤버 목록은 볼 수 있음 (읽기 전용)
  - 초대 폼 숨김
  - "멤버 초대 권한이 없습니다" 메시지 표시

**인터랙션**:
- **이메일 입력**:
  1. 사용자가 이메일 입력
  2. 300ms 디바운싱 후 자동 검색
  3. 검색 결과 selector 표시
  
- **사용자 선택**:
  1. 검색 결과에서 사용자 클릭
  2. 입력 필드 아래 배지로 표시
  3. 검색 결과 숨김
  
- **역할 선택**:
  - 드롭다운에서 역할 선택
  - 기본값: "멤버"
  
- **초대하기 버튼 클릭**:
  1. `inviteMemberAction()` 호출
  2. 로딩 상태: 버튼 비활성화 + 스피너
  3. 성공 시:
     - 멤버 목록 자동 갱신
     - 초대 폼 초기화
     - Toast: "[이름]님에게 초대를 보냈습니다"
     - 초대 목록에 "초대 중" 상태로 표시
  4. 실패 시:
     - Toast 에러 메시지
     - 폼은 입력 상태 유지

**에러 처리**:

## 📍 Scenario 3: 멤버 역할 변경

### 비즈니스 컨텍스트

## 🎨 UI/UX 패턴 정리

### 권한 기반 UI (Layered Authorization)

**프론트엔드 레이어 (UX 최적화)**:
- **목적**: 사용자 경험 향상, 불필요한 API 호출 방지
- **구현**:
  - 권한 없는 UI 요소 숨김 또는 비활성화
  - 현재 상태 체크 표시
  - 조건부 렌더링
- **보안**: 보안 목적 아님 (클라이언트 코드 우회 가능)

**백엔드 레이어 (Security Enforcement)**:
- **목적**: 실제 보안 검증
- **구현**:
  - DB 조회 기반 권한 확인
  - 비즈니스 규칙 강제
  - 모든 요청 검증
- **보안**: 진짜 보안 (서버 실행, 우회 불가)

### 일관된 에러 처리

**성공 피드백**:
- Toast 메시지 (우측 상단, 3초 표시)
- 녹색 배경 + 체크 아이콘

**실패 피드백**:
- Toast 메시지 (우측 상단, 5초 표시)
- 빨간색 배경 + X 아이콘
- 구체적인 에러 메시지

**로딩 상태**:
- 버튼 비활성화
- 스피너 표시
- 텍스트 변경 ("생성 중...", "변경 중...")
