## Domain Context and Boundaries

### Domain Overview

This section provides the context and boundaries for the Artifact Template domain, including its purpose, scope, and relationship to other domains.

### Domain Purpose

The Artifact Template domain is responsible for artifact template definition and management. One of the 7 core node types that defines artifact structure and format (flow, markdown, table, custom). It handles template creation with Node Definition, Edge Definition, and Column Definition sub-nodes, template customization through Editor Panel interfaces, and auto-generation of Artifact Class nodes for design mode connections. This domain ensures consistent artifact structure and formatting across the platform.

### Domain Boundaries

- **In Scope**: Artifact template definition with format types (flow, markdown, table, custom), Node Definition/Edge Definition/Column Definition sub-nodes, Editor Panel metadata management, auto-generation of Artifact Class nodes, template structure validation, template customization through specialized tools
- **Out of Scope**: Actual artifact generation (Execution domain), workflow design and orchestration (Workflow domain), agent persona and role definitions (Agent domain), visual canvas rendering and Editor Panel UI implementation (Canvas domain), task input/output edge management (Task domain)
- **Boundaries**: Clear separation between artifact template definition (design mode structure) and artifact generation (execution mode outputs), with templates providing structure blueprints for execution outputs

### Key Entities

- **ArtifactTemplate**: The core entity representing one of the 7 core node types with artifact structure and format definitions, stored as a node with type 'artifact_template'
- **NodeDefinition**: Sub-node that defines custom node types for flow format templates, including metadata schema and design properties
- **EdgeDefinition**: Sub-node that defines custom edge types for flow format templates, including style properties and metadata schema
- **ColumnDefinition**: Sub-node that defines column structure for table format templates, including data types and validation rules
- **ArtifactClass**: Auto-generated abstract representation of artifacts for design mode connections, created when templates are defined
- **TemplateMetadata**: Essential template information including development slug, display name, artifact format type, and layout configuration

### Ubiquitous Language

- **Artifact Template**: One of the 7 core node types that defines the structure, format, and organization of artifacts generated by agents, stored as a node with type 'artifact_template'
- **Template Node**: The definition of an artifact template with format and sub-node configurations stored as a node in the Universal Node System
- **Artifact Format**: Classification of templates based on output type (flow, markdown, table, custom format)
- **Node Definition**: Sub-node that defines custom node types for flow templates, including AI instructions and metadata schemas
- **Edge Definition**: Sub-node that defines custom edge types for flow templates, including style properties and connection rules
- **Column Definition**: Sub-node that defines table column structure, including data types and validation rules
- **Editor Panel**: A z-index overlay interface that appears when templates are selected, allowing metadata editing and sub-node management
- **Artifact Class**: Auto-generated abstract representation that enables design mode connections before actual artifacts are created
- **Template Builder Tools**: Context-specific definition node creation tools (Node/Edge/Column Definition) available in Top Toolbox for simple placement without connections
- **Universal Node System**: The foundational architecture where artifact templates are stored as nodes with hierarchical sub-node relationships

## Universal Node System Integration

### Artifact Template as Node Architecture

**Core Principle**: Artifact Templates are stored as nodes within the Universal Node System, with their format definitions and sub-node configurations defined in the node metadata.

**Node Structure**:

- **ArtifactTemplate Node**: Type 'artifact_template', contains format type, layout configuration, and metadata
- **Sub-Node Relationships**: Contains Node Definition, Edge Definition, and Column Definition sub-nodes through "contains" edges
- **Auto-Generated Artifacts**: Creates corresponding Artifact Class nodes automatically for design mode connections
- **Parent Relationships**: Artifact Templates can be contained within Agent nodes or exist as standalone project components
- **Editor Panel Integration**: Template metadata can be edited through context-aware overlay interfaces

## Business Rules and Policies

### Artifact Template Node Definition Rule

**Business Context:**
Artifact Templates must be properly defined as nodes within the Universal Node System with complete format specifications and sub-node relationships.

**Rule Logic:**

- Artifact Templates must be stored as nodes with type 'artifact_template'
- Template metadata must include development slug, display name, and artifact format
- Artifact format must be one of the supported types (flow, markdown, table, custom)
- Template slugs must be unique within the workspace for identification
- Template nodes must have valid hierarchical relationships with sub-nodes
- Auto-generation of corresponding Artifact Class nodes must occur upon template creation

**Implementation Details:**

- **Priority**: Critical
- **Enforcement**: Node creation and validation through Editor Panel
- **Applicable Entities**: ArtifactTemplate, TemplateNode, TemplateMetadata, ArtifactClass
- **Business Owner**: Artifact Template Domain Owner

**Exceptions and Edge Cases:**

- Experimental templates may have incomplete sub-node definitions during design
- Legacy templates may require migration to new sub-node structure

**Related Rules:**

- Template Format Validation Rule
- Sub-Node Management Rule

---

### Sub-Node Definition Management Rule

**Business Context:**
Artifact Templates must properly manage their definition sub-nodes (Node Definition, Edge Definition, Column Definition) which are created via Top Toolbox for individual placement without automatic connections.

**Rule Logic:**

- Flow format templates must contain Node Definition and Edge Definition sub-nodes created through Top Toolbox
- Table format templates must contain Column Definition sub-nodes created through Top Toolbox
- Markdown and custom format templates may have optional sub-nodes
- Definition sub-nodes are placed individually via Top Toolbox tools without automatic inter-connections
- Sub-nodes maintain hierarchical relationship to parent template through "contains" edges
- Sub-node definitions must include complete metadata schemas and configuration as individual class definitions
- Sub-node modifications must trigger validation and update parent template

**Implementation Details:**

- **Priority**: Critical
- **Enforcement**: Sub-node validation and relationship management
- **Applicable Entities**: ArtifactTemplate, NodeDefinition, EdgeDefinition, ColumnDefinition, ContainsEdge
- **Business Owner**: Artifact Template Domain Owner

**Exceptions and Edge Cases:**

- Custom format templates may have flexible sub-node requirements
- Complex templates may require multiple definition types

**Related Rules:**

- Artifact Template Node Definition Rule
- Template Format Validation Rule

## Domain Events and Notifications

### Event-Driven Policies

This section defines the domain events that trigger policy enforcement and the notification mechanisms for policy violations.

### Policy Enforcement Events

- **Event**: ArtifactTemplateCreated
- **Trigger**: New artifact template node created through Editor Panel
- **Policy**: Artifact Template Node Definition Rule, Template Format Validation Rule
- **Action**: Validate template format and metadata, auto-generate Artifact Class node, notify stakeholders

- **Event**: TemplateFormatModified
- **Trigger**: Artifact format type or layout configuration changed through Editor Panel
- **Policy**: Template Format Validation Rule, Sub-Node Definition Management Rule
- **Action**: Validate format compatibility, update sub-node requirements, update Artifact Class

- **Event**: SubNodeCreated
- **Trigger**: Node Definition, Edge Definition, or Column Definition sub-node created
- **Policy**: Sub-Node Definition Management Rule, Sub-Node Relationship Validation
- **Action**: Validate sub-node type compatibility, establish "contains" relationship, update parent template

- **Event**: SubNodeModified
- **Trigger**: Sub-node metadata or schema definitions updated
- **Policy**: Sub-Node Definition Management Rule, Metadata Schema Validation
- **Action**: Validate sub-node configuration, update metadata schema, propagate changes to parent

- **Event**: ArtifactClassGenerated
- **Trigger**: Artifact Class node auto-generated from template
- **Policy**: Artifact Class Generation Rule, Design Mode Integration Rule
- **Action**: Create Artifact Class node, establish connections, enable design mode usage

- **Event**: TemplateBuilderToolUsed
- **Trigger**: Top Toolbox template builder tools accessed for definition node placement
- **Policy**: Template Builder Tool Access Rule, Context Validation Rule
- **Action**: Validate tool context and permissions, enable individual definition node placement without automatic connections
