# Project Brief: xbowl - Scratch for AI Agents

## Executive Summary

**Product Concept:** xbowl is a visual AI agent workflow platform that enables users to design, orchestrate, and deploy complex AI agent teams through an intuitive 2D canvas interface, making AI agent creation as accessible as visual programming for children.

**Primary Problem:** Current AI agent orchestration requires deep technical expertise and complex coding, making it inaccessible to 99% of people who could benefit from AI agent teams. Everyday people can't easily create their own AI agent teams or "hire" AI agents like human team members.

**Target Market:**

- Service providers wanting to automate workflows (development agencies, film studios, investment analysts)
- Educational users (students, educators)
- Content creators (webtoon artists, journalists)
- Individual creators wanting to build AI-powered businesses

**Key Value Proposition:** Democratize AI agent orchestration by providing a visual, collaborative platform where users can design complex AI workflows as easily as creating a flowchart, enabling anyone to build their own AI-powered virtual teams.

## Problem Statement

**Current State & Pain Points:**

- AI agent orchestration currently requires deep technical expertise and complex coding
- **Everyday people can't easily create their own AI agent teams** - it's limited to developers and tech companies
- No visual tools exist for designing AI workflows - everything is code-based
- **Regular users can't "hire" or "manage" AI agents** like they would human team members
- Difficult to understand and communicate AI agent interactions and data flow
- Hard to iterate and refine AI workflows without visual feedback
- No collaborative design environment for AI agent teams

**Impact of the Problem:**

- **AI agent teams remain inaccessible to 99% of people** who could benefit from them
- Limits AI adoption to technical teams only
- **Prevents individuals from creating their own AI-powered businesses or services**
- Slows down AI workflow development and iteration
- Makes it difficult to share and reuse successful AI workflows
- Creates barriers to creating complex, multi-agent systems

**Why Existing Solutions Fall Short:**

- Current AI platforms focus on individual agents, not workflow orchestration
- **No platform exists where regular people can "hire" and "manage" AI agent teams**
- No visual design tools for AI logic and data flow
- Lack of collaborative features for team-based AI workflow design
- Existing workflow tools (like Zapier) are too simplistic for complex AI logic

**Urgency & Importance:**

- **There's a massive untapped market of people who want AI agent teams but can't access them**
- AI agent adoption is growing rapidly but limited by technical barriers
- Visual design tools have democratized other complex domains (design, data analysis)
- **This could enable millions of people to create their own AI-powered businesses**

## Proposed Solution

**Core Concept & Approach:**
xbowl is a visual AI agent workflow platform that enables **anyone** to create, manage, and deploy AI agent teams through natural language and 2D canvas interactions - **no coding required**. Think "Scratch for AI agents" with a Notion-inspired universal node system - as intuitive as visual programming for children.

**Key Differentiators:**

- **Natural Language Agent Definition**: Users can describe agents, tasks, and workflows in plain English/Korean, and the platform translates this into executable AI agent configurations
- **Visual 2D Canvas Design**: Intuitive drag-and-drop interface where users can visually design agent interactions, data flows, and workflow logic
- **Scratch-like Simplicity**: **As easy as teaching elementary school students to code** - visual blocks, drag-and-drop, immediate visual feedback
- **Democratized Access**: Enables non-technical users to create sophisticated AI agent teams that previously required development expertise
- **Agent Team Management**: Users can "hire," "fire," "train," and "manage" AI agents like human team members
- **Dual Canvas System**: Separate design mode for workflow creation and execution mode for monitoring and interaction
- **Universal Node System**: Notion-inspired unified data model where everything is a node, enabling seamless extensibility and consistency

**Why This Solution Will Succeed:**

- **Lowers the barrier to entry** from "requires programming skills" to "as easy as Scratch programming"
- **Visual design approach** has proven successful in other domains (Figma, Canva, Notion)
- **Natural language interface** makes AI agent creation accessible to everyone
- **Enables new use cases** - individuals can create AI-powered businesses without technical teams
- **Educational approach** - users learn by doing, with immediate visual feedback

**High-Level Vision:**
A platform where **anyone** - from students to business owners - can visually design AI agent teams using simple drag-and-drop nodes and natural language, just like creating animations in Scratch, then deploy and manage those teams to automate complex workflows through a unified node-based system.

#### 2. **Universal Node System**

**Core Innovation**: Inspired by Notion's block system, everything in xbowl is a node - from workflow components to generated artifacts. This unified approach provides consistency, extensibility, and simplicity.

**Key Benefits**:

- **Unified Data Model**: All entities (agents, workflows, artifacts, custom nodes) use the same node structure
- **Type-Instance Separation**: NodeType (class definition) and UniversalNode (instance data) are clearly separated
- **Extensible Node Types**: Users can define custom node types at runtime through templates
- **Hierarchical Organization**: Parent-child relationships through `parent_id` references
- **Consistent API**: Single CRUD interface for all node types
- **Scalable Architecture**: Efficient database design with proper indexing
- **Visual Customization**: Each node type has defined styles with individual node override capability

**Node Types**:

**System-Defined Nodes (Design Mode)**:

- `agent`: Individual AI agents with personas, roles, and capabilities
- `agent_team`: Groups of agents with collaboration rules
- `task`: Specific tasks with markdown instructions, input/output edges, and variable parameters
- `workflow`: Orchestration of agents, tasks, and flow control nodes with sequence definitions
- `artifact_template`: Template definitions for artifact structure and format (flow, markdown, table, custom)
- `checklist`: Validation and quality assurance checklists with markdown content
- `data`: Reference data and information with markdown content
- `artifact_class`: Abstract representation of artifacts for design mode connections (auto-generated from templates)

**Runtime-Generated Nodes (Execution Mode)**:

- `page`: Custom page nodes (defined by artifact templates)
- `component`: Custom component nodes
- `data_model`: Custom data model nodes
- `*`: Any user-defined node type through templates (contained within artifacts)

**Data Model**:

```typescript
// Node Type Definition (Class/Type)
interface NodeType {
  id: string;
  name: string; // 'agent', 'page', 'component', etc.
  category: "system" | "custom"; // System-defined vs User-defined
  description: string;
  properties: NodeProperty[]; // Required properties for this node type
  style: NodeStyle; // Visual style definition
  renderer: string; // Which renderer to use
  created_by?: string; // For custom types, who created it
  created_at: Date;
  updated_at: Date;
}

interface NodeProperty {
  name: string;
  type: "string" | "number" | "boolean" | "object" | "array";
  required: boolean;
  default?: any;
  validation?: any; // Zod schema
  description: string;
}

interface NodeStyle {
  icon: string; // Icon
  color: string; // Default color
  shape: "rectangle" | "circle" | "diamond" | "custom";
  size: { width: number; height: number };
  border: { style: string; width: number; color: string };
  background: { color: string; opacity: number };
}

// Node Instance (Actual node data)
interface UniversalNode {
  id: string;
  type_id: string; // References NodeType
  parent_id?: string; // Hierarchical structure
  content: any; // Data matching NodeType properties
  metadata: {
    created_at: Date;
    updated_at: Date;
    status: "draft" | "active" | "archived";
    version: number;
    user_id: string;
  };
  position?: { x: number; y: number }; // For visual nodes
  style_override?: Partial<NodeStyle>; // Individual node style override
}

interface NodeRelationship {
  id: string;
  source_node_id: string;
  target_node_id: string;
  relationship_type: string; // 'sub', 'include', 'executes', 'contains', etc.
  data?: any;
}
```

#### 3. **Universal Node-Based Workflow System**

**Core Innovation**: All workflows, artifacts, and their components are unified under the Universal Node System, providing seamless integration between design and execution modes.

**Key Benefits**:

- **Seamless Mode Transition**: Same node structure used in both design and execution modes
- **Progressive Node Generation**: Nodes created incrementally with real-time visual feedback
- **Template-Driven Customization**: Users define custom node types through templates
- **Hierarchical Organization**: Natural parent-child relationships for complex structures
- **Consistent User Experience**: Same interaction patterns across all node types

**Workflow Architecture**:

```
Design Mode:
workflow_node (type_id: 'workflow-type')
├── agent_node (type_id: 'agent-type', parent_id: workflow_id)
├── task_node (type_id: 'task-type', parent_id: workflow_id)
└── template_node (type_id: 'template-type', parent_id: workflow_id, content: { custom_types: [...] })

Execution Mode:
artifact_node (type_id: 'artifact-type', parent_id: workflow_id, content: { type: 'flow', template_id: template_id })
├── page_node (type_id: 'page-type', parent_id: artifact_id, content: { title: 'Home', content: '...' })
├── component_node (type_id: 'component-type', parent_id: artifact_id, content: { name: 'Header', props: {...} })
└── relationship (source: page_id, target: component_id, type: 'contains')

Note: artifact_node is System-Defined, while page_node and component_node are Runtime-Generated custom nodes
```

**Progressive Node Generation**:

```
Task: create ia
Template: { custom_types: ['page', 'component', 'data'] }
Output Process:
1. LLM → create_node(type_id: 'artifact-type', parent_id: workflow_id, content: { type: 'flow', template_id: template_id }) → DB 저장 → 즉시 렌더링
2. LLM → create_node(type_id: 'page-type', parent_id: artifact_id) → DB 저장 → 즉시 렌더링
3. LLM → create_node(type_id: 'component-type', parent_id: artifact_id) → DB 저장 → 즉시 렌더링
4. LLM → create_node(type_id: 'data-type', parent_id: artifact_id) → DB 저장 → 즉시 렌더링
5. LLM → create_relationship(source: page_id, target: component_id, type: 'contains') → DB 저장 → 즉시 렌더링
```

**Template System**:

```yaml

        description: "Data models and schemas"

          icon: "🗄️"

    - references: "Cross-references between nodes"
    - implements: "Implementation relationships"
```

### Open Questions (Resolved)

**Technical Questions:**

1. ✅ **Complex workflow logic**: BMAD method proves natural language + semantic processing is sufficient. Modern agents with thinking mode and extended context length can handle conditional branching and loops through semantic understanding, eliminating the need for complex programming logic.

2. ✅ **Agent communication**: Artifact-based communication system where all agents are completely stateless within the same workflow, sharing no sessions. Communication occurs through meticulously engineered context dependencies, primarily through artifacts generated by other agents (e.g., project-brief.md passed to PRD creation agent). This mirrors real-world workplace document handoffs between team members.

3. **Security/privacy**: To be addressed post-MVP with comprehensive data protection and compliance measures.

3. ✅ **Monetization**: Token-based pricing model (similar to Cursor AI) with tiered limits and additional charges for overages. Marketplace revenue sharing for workflow rentals, with special pricing tiers for students. Investment funding may be required to support freemium model due to API costs.
